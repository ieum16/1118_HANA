# 주간업무회의 대시보드 인수인계

기준일 2026-11-19

## 만들게 된 이유

주간회의 자료 취합 담당자 한 명이 팀원별 추진 업무와 운영 이슈를 모으고, 이미 집계된 캠페인 수치를 회의자료 표에 옮깁니다. 이 과정은 매주 약 30분이 걸렸습니다. 대시보드는 이 내용을 주차별로 정리해 보고에 첨부할 편집 가능한 Word 파일을 만드는 데 쓰입니다.

## 현재 사용 흐름

1. **보고 주**를 선택합니다. 캠페인 집계 기간은 선택한 주의 직전 월요일부터 일요일까지입니다.
2. 상단 가로표에 발송 건수, 실행 건수, 문자·푸시·인앱별 발송 건수, 사용 부서 수를 입력하거나 집계표에서 붙여넣습니다. 실행 건수는 손님 수 기준으로 중복을 포함한 원본 집계값을 사용합니다. KPI 카드와 차트가 입력값에 맞춰 갱신되고, 최근 6주 차트에서 미입력 주는 비어 있습니다.
3. **이번 주 운영 이슈**는 제목과 본문을 별도 입력칸에 적습니다. **이번 주 추진 업무**는 단위 업무명 아래에 현황·개선 전·개선 후를 필요한 만큼 여러 줄로 적습니다.
4. **Word 파일 저장**으로 선택한 주의 자료를 내려받습니다. 문서 순서는 캠페인 가로표, 운영 이슈, 추진 업무입니다. 이슈 제목과 본문은 별도 문단으로 나옵니다.

[운영 대시보드](https://weekly-work-dashboard-taupe.vercel.app/)

## 파일과 배포

| 위치 | 역할 |
|---|---|
| 작업 폴더의 `my-os/index.html` | 브라우저에서 그대로 여는 작업 원본. 화면, 저장, 차트, Word 생성이 한 파일에 들어 있습니다. |
| Vercel에 연결된 배포 저장소의 `main` | 운영 HTML 배포 경로. [배포 저장소](https://github.com/pyppi0442-png/weekly-work-dashboard) |
| 수업 저장소의 `실습3_나만의도구/박은정/` | 제출본. 여기서 실행 파일과 기획서, 테스트, 가상 데이터 화면을 확인할 수 있습니다. [최초 제출 커밋](https://github.com/ieum16/1118_HANA/commit/ce23a0ced9c870ff7f19f65bb754a1180149f43f) |

코드 수정은 작업 원본에서 시작합니다. 로컬에서 확인한 뒤 배포 저장소에 올리고 운영 주소에서 변경을 확인합니다. 수업 제출본을 갱신할 때는 이 폴더에 확인한 파일을 복사하고 함께 변경된 테스트나 화면 캡처를 맞춥니다. [실행 파일](index.html) · [기획서](prd.md) · [테스트 기록](test.md)

입력 자료는 접속 주소와 브라우저 프로필별로 저장됩니다. 로컬 HTML에서 작성한 기록을 Vercel에서 이어 쓰거나 다른 PC로 옮길 때는 JSON **백업**과 **복원**을 사용합니다. 복원은 해당 브라우저의 주차별 기록 전체를 교체하므로 먼저 현재 자료를 백업합니다. 실습과 공유에는 가상 데이터를 사용합니다.

## 확인한 범위

표 붙여넣기와 숫자 검증, 주차 이동과 저장, JSON 백업 복원, 모바일 배치, KPI 갱신을 브라우저에서 확인했습니다. 생성된 `.docx`의 표와 문단, 한글과 줄바꿈도 파일 구조를 읽어 확인했습니다. Microsoft Word 데스크톱에서 파일을 여는 검증과 주간 작성 시간 절감 측정이 남아 있습니다.

## 다음에 진행할 순서

1. **Microsoft Word 데스크톱에서 회의자료 한 건을 확인합니다.** 가상 데이터로 주차 하나를 작성하고 `.docx`를 저장합니다. Word에서 복구 메시지 없이 열리는지 확인한 뒤, 캠페인 표의 6개 열과 집계 기간, 운영 이슈의 줄바꿈, 긴 추진 업무가 다음 페이지로 넘어가는 모양을 봅니다. 표와 본문을 수정하고 저장한 뒤 다시 열 수 있으면 완료로 기록합니다.
2. **기존 보고 양식과 대조합니다.** 공유 가능한 가상 예시나 빈 양식으로 제목, 필수 열, 표 순서와 페이지 여백을 비교합니다. 첨부에 필요한 차이를 Word 내보내기 서식에 반영합니다.
3. **한 주치 자료를 시험 취합하고 시간을 잽니다.** 팀원 작성 내용을 붙여넣는 시점부터 Word 검토까지 걸린 시간을 기존 약 30분과 비교합니다. 추가로 손이 가는 단계가 있다면 그 단계부터 개선합니다.
