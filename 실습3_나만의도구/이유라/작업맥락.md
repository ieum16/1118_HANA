## 사용자와 만들고 싶은 것

닉네임은 봉봉에서 이유라로 변경했고 자기소개와 실습 1·2·3 폴더 이름도 변경해 제출했다. 본부·기획·공통 업무에서 자료를 자주 정리한다. 설명은 쉬운 말로, 사용 방법과 확인할 결과 중심으로 안내하면 좋다.

업무 메모가 흩어져 지난주에 한 일이 잘 기억나지 않고, 미뤄진 계획의 진행 상황을 보고용 문장으로 정리하는 데 시간이 든다. 기존에는 메모장에 초안을 쓰고 컨플루언스에 옮겼다. 별도 주간노트 페이지로 업무를 모으고 보고서 표를 복사하는 방식으로 결정했다.

## 주간노트에서 유지할 사용 방식

- 평소 짧게 메모하고 금요일에 모아 정리한다. 한 번에 여러 건을 입력하는 방식도 지원한다.
- 보고서 열은 업무명, 전주 실적, 이번 주 계획, 특이사항, Due-date다.
- Due-date는 선택한 보고 대상 주 안에서 해당 업무를 끝낼 예정일이다. 주 시작은 월요일이다.
- 전주 계획을 가져와도 완료 실적으로 자동 확정하지 않는다. 진행 상황과 다음 조치를 직접 확인하고 이전 주 기록을 보존한다.
- 문구는 상태와 입력 내용을 조합해 제안한다. 자유 문장을 다듬는 외부 AI 기능은 향후 아이디어다.
- 컨플루언스 직접 연동은 요청 범위에서 제외하기로 했다. 독립 페이지에서 보고서를 복사해 사용한다.
- 최종 화면은 은은한 세이지 그린, 주아체, 웃는 별 캐릭터가 들어간 세 영역 제목이다. ‘한 주의 업무를, 한눈에.’에는 타이핑 효과가 있다.

## 파일 위치와 다음 편집 시 주의할 점

현재 PC의 작업 기준 폴더는 `C:/Users/User/Desktop/바이브코딩`이다. 다른 PC에서는 아래 상대 경로를 기준으로 찾는다.

| 상대 경로 | 용도 |
|---|---|
| `todo-extension/` | 확장 프로그램의 최신 로컬 작업본 |
| `TEAM!/` | 집안일 쉼표 작업본과 기획서·제작 계획서·로고 프롬프트 |
| `GitHub/Team-Page/` | 집안일 쉼표 개인 저장소의 로컬 체크아웃 |
| `my-os/` | 주간노트 작업본 `index.html`, `os-prd.md`, `os-build-plan.md` |
| `Weekly-action/index.html` | 주간노트 개인 저장소에 올릴 때 사용한 파일. 이 폴더 자체에는 로컬 Git 저장소가 확인되지 않았다 |
| `GitHub/1118_HANA/` | 수업 저장소의 로컬 체크아웃. 실습별 이유라 폴더가 제출본 |

정리 시점에 `my-os/index.html`, `Weekly-action/index.html`, 실습 3 제출본은 SHA-256이 일치했다. 집안일 쉼표의 `TEAM!` 작업본과 개인 저장소 HTML은 일치했고 수업 제출본도 Git 비교에서 내용 차이가 없었다.

확장 프로그램은 제출 뒤 적용한 주아체가 로컬에만 있다. 제출본과 비교하면 `popup.css`가 다르고 `fonts/Jua-Regular.ttf`, `fonts/OFL.txt`가 로컬에 추가되어 있다. 다음 작업에서 이 세 파일을 함께 반영해야 한다.

`work-os-builder`는 현재 PC의 `C:/Users/User/.codex/skills/work-os-builder/`에 전역 설치되어 있다. 다른 PC에서는 설치 상태를 먼저 확인한다.

## 검증 결과와 아직 확인할 것

주간노트는 기존 작업에서 코드 기반 점검 20개를 통과했다. 이후 타이핑 효과와 글꼴·별 캐릭터·색상을 점검했고, 배포 화면을 열어 가상 예시와 세 영역이 표시되는 것을 확인했다. 세부 결과는 [test.md](test.md)에 있다.

실제 브라우저 조작으로 메모 저장 후 새로고침, 백업 파일 저장·복원, 보고서 복사·붙여넣기, 공백 입력, 375px 화면 확인이 남아 있다. 컨플루언스 편집기에서의 최종 붙여넣기 결과도 미확인이다. 절약 시간은 아직 측정하지 않았다.

실습 2 README의 ‘만들면서 배운 점’은 사용자 소감 입력을 기다리는 상태다. 원래 요청했다 취소한 달러 환율 추이 그래프는 구현하지 않았다.

## 저장소 작업 방식

수업 저장소의 `AGENTS.md`와 `.me.json`을 먼저 읽는다. 수정 범위는 이유라의 자기소개와 실습 1·2·3 폴더다. 파일을 개별 경로로 지정해 올리고 다른 사람의 변경은 보존한다. 정리 시점에 자기소개 폴더의 추적되지 않은 스크린샷 한 개가 있었으며 이번 문서 업로드 대상에서 제외한다.

개인 저장소는 배포 소스이고 수업 저장소는 과제 제출 위치다. 기능을 고치면 작업본·개인 저장소·제출본 중 어디에 반영했는지 기록한다. 업로드 후 원격 파일 또는 커밋을 확인하고 Vercel 반영도 별도로 확인한다.
