## 3. DT 업무 포털 — DT_teampage

### 목적과 결정된 방향

팀 소개에서 출발해 그룹 직원이 장애·인프라 현황을 보고, DT팀이 계약과 운영 정보를 관리하는 포털로 확장했다.
바쁜 사용자가 핵심을 바로 볼 수 있도록 장애를 최상단에 표시한다.

- 역할은 직원 / 관리자 / DT 세 가지. 업무 전체·영업·운용 필터는 제거했다.
- 직원은 공통 장애·인프라·제안을 확인한다. 관리자는 계약 조회까지, DT는 등록·수정·삭제까지 한다.
- 계약은 단말기·데이터·프로그램 라이선스, 업체명·기간·만료일·경비/자본 예산 구분을 다룬다.
- 전광판은 계단측·벽면·천장 세 종류를 하나의 카드로 묶는다.
- 전광판 컨트롤러는 새 탭으로 여는 예시 URL이다. 실제 장비 연결이 아니다.
- 프로그램 운영의 세부 내용은 미정이어서 준비 중으로 남겼다.
- 디자인은 초록·흰색에서 검정 배경·형광 초록·모노스페이스·CRT 스캔라인으로 변경했다. 이전 버전은 index-before-crt.html이다.

### 현재 구현과 저장 범위

| 데이터 / 기능 | 현재 상태 |
|---|---|
| 자동화 제안 | /api/ideas와 Private Vercel Blob으로 서버 저장·공유 |
| 제안 갱신 | 목록 새로고침, 재방문·창 복귀, 열린 동안 1분 간격 |
| 예전 브라우저의 제안 | 해당 PC에서 업데이트된 배포 사이트를 다시 열면 자동 전송 |
| 제안 저장 실패 | 성공으로 표시하지 않고 전송 대기로 남겨 재시도 |
| 인프라·계약·장애 | 브라우저 localStorage. 다른 PC와 공유되지 않음 |
| 역할 전환 | 화면 시안용 선택. 실제 로그인·서버 권한 검사는 미구현 |
| 백업 | JSON 내보내기 지원. 백업 가져오기는 미구현 |

제안 공유 문제는 다른 PC에서 등록한 내용이 보이지 않는다는 요청으로 수정했다.
독립된 두 브라우저에서 같은 제안이 보이는 것을 이전 작업에서 확인했다.
동시 등록 충돌·중복 재시도·서버 저장 실패 등을 다루는 테스트가 있다.
역할별 표시, CRUD, 새로고침 복원, 375px 모바일 화면은 이전 작업에서 확인한 기록이 있다. 이 문서 작성 중 기능 테스트를 다시 실행한 것은 아니다.

### 이어서 볼 파일

- api/ideas.js, lib/ideas-handler.js: 제안 서버 기능

API·공유 확인은 로컬 파일 더블클릭만으로 완료할 수 없으므로 배포 환경까지 확인한다.

## 4. 간단 조치 안내 도구 — automated_msg

### 사용자 요구가 바뀐 핵심

초기에는 장애 접수·진행·복구 메시지 작성기였지만, 사용자는 **단순 문의에 조치 방법을 순서대로 안내하고, 해결되지 않으면 담당자 연락처를 전달하는 도구**를 원한다고 정정했다.
이것이 현재 제품 방향이다. 발생 시각·원인·진행 상태 중심의 보고서 입력으로 되돌리지 않는다.

### 현재 기능과 결정

- 문의 유형 → 제목·조치 방법 → 연락처 선택 → 안내문 생성·직접 수정·복사.
- 줄마다 한 단계로 입력하면 순서를 붙이고 빈 줄을 제외한다.
- 연락처는 업체명·담당자명·역할·전화·이메일·여러 장애 유형·메모로 관리한다.
- 같은 업체에 여러 담당자, 한 담당자에 여러 장애 유형을 연결할 수 있다.
- 현업/업체 전달 대상 선택은 제거했다.
- 업체명 + 담당자명으로 중복을 판단한다. 같은 내용은 알리고 추가하지 않으며, 변경된 내용은 기존 정보에 업데이트한다.
- 신규 화면을 통한 업데이트와 명시적 수정 화면의 삭제·유형 해제 처리는 구분한다. 세부 규칙은 prd.md를 따른다.
- 디자인은 검정·옵시디언·네온 라임 버튼·유리 카드·모바일 한 열 구성이다. DT 포털의 CRT 디자인과 별개다.

### 현재 상태와 한계

문서 작성 시 GitHub main에 index.html, 기획·테스트·디자인 문서, package.json, scripts/, vercel.json이 있는 것을 확인했다.
최신 채팅 결과를 다시 확인한 결과 GitHub 업로드와 빌드는 완료됐다. Vercel이 이메일 본인 확인을 요구해 배포는 대기 중이다. 사용자가 Chrome의 Vercel 화면에서 이메일의 6자리 코드를 직접 입력하고 Verify Code를 누른 후, 기존 배포 채팅에 인증 완료를 알려야 한다. 인증 코드는 문서·채팅·저장소에 기록하지 않는다. 최종 배포 URL은 아직 확정하지 않았다.

연락처는 브라우저 localStorage에만 저장된다. PC·브라우저 간 공유가 없고, 로컬 파일과 배포 사이트의 저장 공간도 다르다.
안내문과 작성 중 입력은 새로고침하면 초기화된다. 연락처 백업·복원, 사용자 템플릿 저장은 아직 없다.
24개 기능 시나리오를 Node VM·최소 DOM 모형으로 확인한 기록이 있으나, 실제 브라우저·클립보드·375px 화면 검증은 남아 있다.

### 실행과 배포

- index.html을 열면 로컬에서 동작한다.
- Node.js 환경에서 npm run build를 실행한다. scripts/build.mjs가 문법을 검사하고 index.html을 dist/로 복사한다.
- Vercel 설정: Other / 루트 ./ / 빌드 npm run build / 출력 dist / 환경변수 없음.
- 문서는 배포용 dist에 복사되지 않는다.
- 먼저 README.md → prd.md → test.md → index.html → scripts/build.mjs 순서로 확인한다.

## 5. 오늘 할 일 크롬 확장

최종 로컬 폴더는 todo-extension_swp이고 manifest 버전은 1.3.0이다.
할 일 추가·완료·삭제·남은 개수, 작성 시각 YYMMDD hhmm, 마감일 달력과 당일·2·3·7·30일 빠른 선택, 날짜 해제 기능을 넣었다.
아이콘은 초록 바탕에 검정색 ‘오’, 화면은 폭 400px·큰 글씨·한국어다.
목록은 chrome.storage.local에 저장한다.

처음 추가한 수동 USD·JPY·EUR 환율·스프레드·우대율·표 붙여넣기는 후속 요청으로 자동 USD/KRW 화면으로 교체했다.
현재는 네이버의 하나은행 현찰 살 때·팔 때 고시 환율과 기준율을 조회한다. 팝업을 열 때와 열린 동안 60초마다 갱신하고, 실패하면 저장된 이전 환율로 표시한다.
이는 거래소 스트리밍 호가가 아니다. 네이버 웹용 공개 응답에 의존하므로 변경 시 README와 tests/fx.test.cjs를 함께 본다.
Node.js 환경에서 node tests/fx.test.cjs로 검증한다.
기존 목록을 유지하려면 확장 프로그램을 제거하지 말고 chrome://extensions에서 새로고침한다.
