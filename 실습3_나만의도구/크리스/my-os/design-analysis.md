# Obsidian & Neon Lime 디자인 분석

> 사용자가 제공한 디자인 설명을 분석한 문서다. 실제 시안 이미지나 구현 화면을 평가한 결과는 아니다. 현재 조치 안내 도구에 대한 적용 제안은 별도로 구분했다. 이 문서 작성으로 기존 화면 스타일을 변경하지는 않는다.

## 1. 디자인의 핵심

이 디자인은 **깊은 검정 위에 네온 라임으로 행동을 강조하는 기술 제품형 인터페이스**다. 검정과 흰색이 기본 정보 구조를 만들고, 라임은 시선을 모으며, 반투명 카드·격자·빛 번짐이 공간감을 더한다.

제시된 구조는 큰 히어로, 기능 소개, 방법론, 추천사, 하단 CTA로 이어지는 **서비스 소개용 랜딩 페이지**에 가깝다. 업무 도구에 적용할 때는 색과 표면 표현을 가져오고, 실제 작업을 늦추는 큰 소개 영역은 축소하는 것이 적합하다.

| 요소 | 시각적 역할 | 사용자에게 주는 인상 |
|---|---|---|
| 블랙·옵시디언 | 화면의 기반, 밝은 요소와의 대비 | 집중감, 절제, 기술적인 분위기 |
| 네온 라임 | 주요 버튼과 핵심 단어 강조 | 즉각적인 행동 유도, 강한 개성 |
| 에메랄드 | 라임과 구분되는 상태 색상 | 저장·완료 등 긍정 상태 표현 |
| 유리 질감 | 배경과 카드 사이에 얇은 층 형성 | 가벼운 부유감, 시각적 깊이 |
| 격자·노이즈 | 평평한 검정 배경에 질감 추가 | 정밀함, 디지털 작업 공간 |
| 거대한 제목 | 메시지의 우선순위 확립 | 자신감, 강한 첫인상 |

## 2. 색상 체계

### 원문에서 지정한 값

| 용도 | 지정값 | 해석 |
|---|---|---|
| 바깥 뷰포트 | `#000000` | 떠 있는 셸 바깥의 검정 여백 |
| 기본 어두운 바탕 | `#0a0a0a` | 스타일 개요에서 언급한 기본색 |
| 셸·표면 | `#0c0c0c` | 세부 사양의 내부 바탕색 |
| 주요 강조 | `#ccff00` | 주요 CTA, 선택 상태, 핵심 강조 |
| 보조 강조 | `#10b981` | 보조 상태 표현용 에메랄드 |
| 주요 텍스트 | `#ebebeb` | 제목과 중요한 본문 |
| 보조 텍스트 | 흰색 60% | 설명·메타데이터 |
| 비활성·약한 텍스트 | 흰색 30% | 비활성 요소·장식적 정보 |
| 유리 표면 | `rgba(255,255,255,0.03)` | 아주 얇은 흰색 오버레이 |
| 기본 테두리 | `rgba(255,255,255,0.1)` | 카드의 경계 |
| 밝은 대비 구간 | `#e5e5e5` | 방법론 섹션의 배경 |

`#0a0a0a`와 `#0c0c0c`는 큰 차이를 만들기보다 표면 깊이를 미세하게 나누는 색이다. 두 색을 임의로 섞기보다 바탕과 카드처럼 역할을 정해 사용해야 한다. 검은 화면에서는 색 차이만으로 카드 경계가 약할 수 있어 테두리와 여백도 함께 필요하다.

### 적용 시 권장 규칙

- 라임은 주요 행동과 선택 상태에 집중한다. 모든 제목과 아이콘을 라임으로 칠하면 강조의 우선순위가 사라진다.
- 라임 버튼에는 검정 글자를 사용한다. 기본 본문은 밝은 회색으로 유지한다.
- 에메랄드는 저장 완료처럼 의미가 있는 상태에 사용한다. 장식용 라임과 완료 상태를 구분하기 쉽다.
- 흰색 30%는 비활성·장식에 한정한다. 필수 입력 라벨, 연락처, 오류 안내는 더 선명하게 표시한다.
- 오류·삭제·주의 상태의 색은 원문에 정의되어 있지 않다. 실제 제품 적용 시 추가 정의가 필요하다.

## 3. 타이포그래피

| 구분 | 원문 사양 | 분석 |
|---|---|---|
| 제목 | Space Grotesk, 300–700, 자간 `-0.06em` | 큰 영문 제목을 조밀하고 강하게 보이게 함 |
| 본문 | Space Grotesk, 400 | 제목과 통일된 인상 유지 |
| 기술 라벨 | JetBrains Mono, 대문자, 넓은 자간 | 시스템 상태·짧은 영문 메타데이터 강조 |
| 히어로 | `7.5rem`, 행간 `0.85` | 소개 문구를 화면의 주인공으로 만듦 |
| 강조 문구 | 이탤릭 + 라임→흰색 그라데이션 | 특정 단어에 시선 집중 |

큰 글자·좁은 자간·짧은 행간의 조합은 짧은 영문 헤드라인에 적합하다. 긴 한국어 제목이나 여러 줄의 작업 안내에 같은 값을 적용하면 읽기 어려워질 수 있다.

**현재 도구에 적용한다면:**

- 큰 제목은 약 32–48px, 본문은 16px 정도를 시작점으로 삼는다. 이는 원문 값이 아닌 적용 제안이다.
- 한국어에는 시스템 한글 글꼴 등 적절한 대체 글꼴을 지정하고, 영문 제목보다 자간을 덜 좁힌다.
- 기술 라벨은 `CONTACTS`, `GUIDE`처럼 짧은 표현에 한정한다. 전화번호·이메일처럼 복사할 실제 데이터의 대소문자를 임의로 바꾸지 않는다.
- HTML 파일 하나로 오프라인 사용한다면 웹폰트 원격 로딩을 기본 전제로 삼지 않는다. 글꼴이 설치되어 있지 않아도 읽을 수 있는 대체 글꼴이 필요하다. 정확한 글꼴 재현이 필수라면 글꼴 파일 포함 방식과 사용 조건을 별도로 결정한다.

## 4. 유리 질감과 배경 효과

### 유리 표면

```css
background: rgba(255, 255, 255, 0.03);
backdrop-filter: blur(16px);
border: 1px solid rgba(255, 255, 255, 0.1);
```

이 표현은 뒤쪽에 격자나 빛 번짐이 있을 때 효과가 두드러진다. 배경이 완전히 단색이면 흐림만으로는 큰 차이가 생기지 않는다. 텍스트가 많은 업무 화면에서는 입력란과 결과 영역의 바탕을 조금 더 불투명하게 두는 편이 읽기 쉽다.

### 장식 효과

| 효과 | 원문 사양 | 적용 판단 |
|---|---|---|
| 격자 | 60×60px, 선형 그라데이션 | 셸 배경에 낮은 대비로 사용 |
| 노이즈 | SVG 오버레이, 불투명도 15% | 실제 패턴의 강도에 따라 거칠기가 달라지므로 화면에서 조정 필요 |
| 글로우 구체 | 큰 방사형 그라데이션, 120px 흐림 | 히어로·배경 모서리에 제한적으로 배치 |
| 부유 애니메이션 | 6초, ease-in-out | 소개용 목업에는 적합. 실제 입력란·버튼에는 적용하지 않는 편이 좋음 |
| 전환 효과 | cubic-bezier(0.4, 0, 0.2, 1) | 탭·버튼·테두리 전환을 통일 |

장식 레이어는 클릭이나 키보드 접근을 막지 않도록 구성한다. 흐림 효과를 지원하지 않는 환경에서도 카드와 텍스트가 구분되어야 한다. 움직임을 줄이는 환경 설정에 맞춰 부유·펄스 효과를 끌 수 있게 한다.

## 5. 레이아웃 구조 분석

### 떠 있는 외곽 셸

검은 뷰포트 안에 최대 너비 1600px, 모서리 2.5rem인 컨테이너를 둔다. 얇은 흰색 테두리와 그림자가 셸을 바깥 배경에서 분리한다.

이 구조의 핵심은 **화면 전체를 하나의 제품 공간으로 묶는 것**이다. 모바일에서는 바깥 여백과 모서리를 줄여 실제 작업 면적을 확보해야 한다.

### 내비게이션

왼쪽의 라임 로고, 가운데 반투명 알약형 메뉴, 오른쪽 상태 표시·흰색 버튼으로 구성된다. 소개용 페이지에서는 여러 섹션 이동을 지원하고, 현재 도구에서는 ‘조치 방법 안내 / 연락처 관리’ 두 탭으로 단순화할 수 있다.

상태 표시는 실제 동작과 일치해야 한다. 서버가 없는 현재 도구에서는 AI 처리 중이나 서버 연결 상태 대신 ‘로컬 사용’, ‘연락처 저장 완료’ 같은 정보가 적합하다.

### 히어로

12열 중 왼쪽 7열은 거대한 소개 문구, 오른쪽 5열은 반투명 목업과 부유 카드가 차지한다. 방문자가 제품을 이해하고 사용하도록 유도하는 구조다.

현재 도구에서는 큰 소개 문구와 가짜 목업을 상단에 두면 입력 화면까지 이동해야 한다. **짧은 제목과 설명 뒤에 실제 입력·결과 영역을 바로 배치**하는 방식이 더 적합하다. AI 라벨·AI 커서는 현재 기능을 설명하는 요소가 아니므로 그대로 사용하지 않는다.

### 벤토 그리드

4열 안에서 2×2 카드, 1×2 카드, 라임 강조 카드를 조합해 특징을 소개한다. 카드 크기로 정보의 중요도를 표현하는 방식이다.

업무 도구에서는 다음처럼 기능 단위로 바꿀 수 있다.

| 카드 | 내용 | 강조 방식 |
|---|---|---|
| 주요 입력 | 문의 유형·제목·조치 순서 | 가장 넓고 안정적인 영역 |
| 결과 | 복사할 안내문 | 입력 옆에 배치하고 충분한 텍스트 공간 확보 |
| 담당자 | 미해결 시 연락할 연락처 | 입력 흐름 안에서 선택·확인 |
| 주요 행동 | 안내문 생성·복사 | 라임 버튼 사용 |

기능과 관련 없는 막대그래프나 색상 견본은 넣지 않는다. 같은 카드 안에 들어가는 정보는 서로 관련되어야 한다.

### 밝은 대비 구간과 푸터

밝은 회색 방법론 구간은 긴 소개 페이지의 리듬을 바꾸는 장치다. 원형 인물 사진과 추천사도 신뢰를 전달하는 마케팅 요소다. 현재 도구에서는 필요성이 낮으므로 생략하거나 짧은 사용 안내로 축소하는 것이 적합하다.

푸터의 거대한 SUPER 워터마크와 대형 CTA는 브랜드 소개 페이지에는 어울리지만, 업무 화면의 기능을 더하지 않는다. 도구명과 연락처 저장 위치 등 짧은 안내로 대체하는 편이 낫다.

## 6. 사양에서 추가로 결정해야 할 부분

원문은 시각적 방향이 명확하지만 구현 가능한 제품 사양으로는 다음이 더 필요하다.

1. **색상 역할:** `#0a0a0a`와 `#0c0c0c`의 정확한 사용 위치, 오류·주의 상태 색상.
2. **반응형:** 12열·4열 레이아웃이 언제 2열·1열로 바뀌는지, 모바일 메뉴 형태.
3. **헤더 동작:** fixed와 absolute 중 하나를 선택하고, 본문 가림 방식을 정리.
4. **상호작용:** 선택·포커스·비활성·오류·로딩 상태와 전환 시간.
5. **장식 강도:** 노이즈 패턴, 글로우 크기·위치, 격자 선의 실제 투명도.
6. **폰트 제공:** 한글 대체 글꼴과 오프라인 환경에서의 글꼴 처리.
7. **콘텐츠:** 로고 이니셜, 실제 제목, 버튼 문구, 시스템 상태의 의미.

## 7. 현재 도구에 대한 최종 적용 제안

**검정 셸 + 라임 주요 버튼 + 얇은 유리 카드**를 디자인의 중심으로 삼는다. 실제 작업은 조치 안내 작성과 연락처 관리이므로 두 화면에 집중한다.

```text
검정 뷰포트
└─ 둥근 옵시디언 셸
   ├─ 로고 · [조치 방법 안내 / 연락처 관리] · 로컬 사용 상태
   ├─ 짧은 제목과 사용 설명
   ├─ 조치 안내 화면
   │  ├─ 왼쪽: 문의 유형 · 제목 · 조치 순서 · 담당자 선택
   │  └─ 오른쪽: 생성한 안내문 · 라임 복사 버튼
   ├─ 연락처 화면
   │  ├─ 왼쪽: 업체명 · 담당자명 · 연락처 · 복수 장애 유형
   │  └─ 오른쪽: 검색 · 필터 · 등록 목록 · 수정·삭제
   └─ 현재 브라우저 저장 안내
```

장식은 배경과 카드 경계에 남기고, 조치 방법·전화번호·이메일이 가장 쉽게 읽히도록 한다. 이 방식이면 제시된 디자인의 개성을 유지하면서 반복 문의 대응이라는 도구의 목적도 살릴 수 있다.
