# 풀스택 개발자 업무 OS — 제품 요구사항 정의서 (PRD)

- 버전: **v1.2** / 2026-11-19
- 상태: **제작 승인 완료, 초기 HTML 구현** (index.html 및 XLSX 미생성)
- 사용자: 가상 소규모 개발팀의 풀스택 개발자 1명. 모든 사람·시스템·프로젝트 정보는 가상 예시.

## 1. 목적 및 문제
개발 작업·이슈 관리, 배포 준비, **운영환경적용요청서 Excel 자동 생성**을 한 화면에서 처리한다. 개발요청서에 있는 요건을 다시 옮겨 쓰고, Git 변경 파일을 수작업으로 정리하고, 테스트 항목별 증적 시트를 복사하는 반복 작업을 줄인다.

가상 인터뷰 가정: 개발자는 하루 8~12건 작업을 확인하고 주 2~3회 배포 요청서를 작성한다. 여러 도구를 오가며 작업 우선순위를 재정리하는 데 하루 30~45분을 사용한다(실측 아님).

## 2. 핵심 모듈 (최대 3개)
1. **개발 작업·이슈**: 작업 추가/수정/삭제, 상태(예정/진행/차단/완료), 우선순위, 마감일, 이슈 집계.
2. **배포 관리**: 배포 대상, 버전, 예정일, 배포·검증·롤백 체크리스트 및 개발요청서 연결.
3. **운영환경적용요청서 작성기**: 기존 개발요청의 개발요건 재사용, 수동 개발사항·테스트방법, Git 변경 파일 목록 반영, 결재자 선택, 테스트 증적 시트 생성, Excel 다운로드.

## 3. 업무 흐름과 데이터 출처
| 단계 | 데이터 | 방식 | 비고 |
|---|---|---|---|
| 개발 시작 전 | 개발요청 ID, 개발요건, 프로젝트/시스템명 | 기존 개발요청서에서 복사·붙여넣기 또는 OS에 사전 등록 | 외부 요청서 시스템 자동 연결은 후속 단계 |
| 개발 진행/완료 | 개발사항 | 개발자 직접 입력 | 배포 건별 저장 |
| 개발 완료 | 신규/추가/변경 프로그램 목록 | Git 변경 이력 기반 | 비교 기준을 명시하고 Git 명령 출력 또는 패치 목록을 수동으로 가져오기 |
| 테스트 준비 | 테스트방법(복수 건) | 개발자 직접 입력 | 테스트 ID, 방법, 기대 결과 |
| 문서 생성 | 신청자, 책임자, 관리자 | 설정값/선택 | 후보자 1명이면 자동 선택 |
| 문서 생성 | Excel 시트 및 증적 링크 | 자동 생성 | 2개 기본 시트 + 테스트별 증적 시트 |

## 4. Git 변경 이력 기반 파일 목록 설계
- 사용자 입력: 프로젝트 식별자(가상), 기준 ref (`base`), 대상 ref (`target`), 비교 방식, 변경 파일 목록 원문.
- 권장 수집: 프로젝트의 로컬 Git에서 `git diff --name-status -M <base> <target>` 실행 후 **출력 텍스트를 붙여넣기**. 예: `git diff --name-status -M origin/main HEAD`. 실제 운영 배포에 포함될 커밋 범위는 사용자가 확인한다.
- A(추가), M(수정), D(삭제), R(이름변경: 기존/신규 경로) 구분. 필요시 C(복사), T(유형변경) 및 미인식 상태는 경고 후 검토 대상으로 표시한다.
- 요청서의 '신규 및 추가 프로그램'에는 추가/수정 파일을 기본 포함하되, 삭제/이름변경은 별도 구분하여 **누락하지 않는다**. 중복 경로 제거 및 정렬, 변경유형·경로·기준/대상 ref 기록.
- **중요 제약**: 단일 오프라인 HTML은 임의의 로컬 Git 저장소나 명령 실행에 접근할 수 없다. v1.2 MVP는 Git 이력에서 **추출한 텍스트를 가져오는 방식**이며, Git 저장소 직접 읽기/자동 수집은 별도 CLI/서버/권한 승인이 필요한 후속 단계다. 커밋 내역이 실제 배포 파일과 동일하다는 보장은 없으므로 최종 확인이 필요하다.
- 보안: 저장소 URL, 토큰, 인증정보는 입력·저장하지 않는다. 경로에 민감한 이름이 있다면 가명 처리한다.

## 5. Excel 문서 구조 (가상 공통 양식)
### Sheet 1: `운영환경적용내용`
1. **개발요청사항**: 연결된 개발요청서의 개발요건 자동 채움(검토·수정 가능).
2. **개발사항**: 개발자 수동 작성.
3. **신규 및 추가 프로그램**: Git 변경 이력의 파일명/경로/상태 자동 반영; 추가·수정·삭제·이름변경 구분 및 비교 ref 표기.
4. **테스트방법**: 개발자 수동 등록 목록(테스트 ID, 테스트 방법, 기대 결과).

### Sheet 2: `결재및테스트목록`
- 결재란: 신청자=OS에 설정된 본인 닉네임 자동 입력; 책임자/관리자는 각각 팀 후보 목록에서 선택. 후보 1명은 자동선택, 0명은 미지정 경고, 2명 이상은 선택 필수. 신청자는 실제 인증된 사용자를 의미하지 않는다.
- 테스트 목록: Sheet 1의 테스트방법 목록을 **같은 순서와 ID로 복제**. 증적 링크 열은 해당 증적 시트로 이동하는 내부 하이퍼링크. 미등록 테스트는 증적 시트를 만들지 않는다.

### Sheet 3~N: `증적_T001`, `증적_T002` ...
- 테스트 1건당 1개 시트. 테스트 ID/방법/기대 결과 자동 기입, 실제 결과/판정(PASS/FAIL/미실행)/실행일/실행자/증적 이미지 영역은 추후 작성용으로 비워 둔다.
- 각 증적 시트에는 Sheet 2 복귀 링크 제공. Excel 시트명 중복·길이(31자)·금지문자를 방지하기 위해 안정적인 테스트 ID 기반으로 명명한다.
- 테스트 0건일 때는 기본 2개 시트만 생성하고 테스트 미등록 경고를 표시한다.

## 7. MVP 구현 제약 및 대안
- 최종 실행 화면은 **index.html 한 파일**, 로그인/서버/외부 전송 없음. 데이터는 localStorage, 전체 JSON 백업·복원 지원.
- 실제 `.xlsx` 다운로드는 브라우저에서 생성 가능한 XLSX 직렬화 로직이 필요하다. **오프라인 단일 HTML 내장 코드로 시트·하이퍼링크·서식을 검증한 뒤 구현**한다. CDN이나 외부 라이브러리를 불러오는 방식은 오프라인 조건에 부합하지 않는다. 기술 검증이 실패하면 HTML만으로 완성되었다고 주장하지 않고, 승인받은 로컬 생성 도구(예: Python/openpyxl)를 별도 후속안으로 제시한다.
- Excel 출력과 Git 자동 수집은 서로 다른 기능이다: Git **변경 이력 기반 입력**은 v1.2 범위, 저장소 직접 조회는 범위 밖.
- 실제 기업 양식/결재 시스템 연동 및 전자서명은 범위 밖. 생성된 문서는 승인 완료 문서가 아닌 **신청 초안**이다.

## 8. 오류·예외 및 검증 기준
- 개발요청 누락, 빈 개발사항, Git 비교 ref 누락, 잘못된 diff 행, 테스트 ID 중복, 결재자 미선택, 테스트 0건에 대해 이해하기 쉬운 경고.
- Excel 파일은 시트 1·2와 테스트 건수만큼 증적 시트를 포함. 테스트 5건이면 총 **7시트**.
- Sheet 1 테스트방법과 Sheet 2 테스트 목록의 ID/순서/내용 일치.
- Sheet 2 링크는 각각 정확한 증적 시트로 이동하며 모든 증적 시트에는 복귀 링크 존재.
- 책임자/관리자 후보 1명일 때 자동 선택, 여러 명이면 사용자가 선택.
- Git A/M/D/R 표본에 대해 경로·상태 정확히 반영, 삭제와 이름변경 누락 없음.
- 새로고침 후 데이터 유지, JSON 백업·복원, 375px 모바일 화면 가로 스크롤 없음.
- 가상 예시 3~5건 및 '예시 지우기' 제공. 실제 업무정보 입력 전 보안정책 확인 안내.

## 9. 보류 및 승인 게이트
- **현재는 기획서와 제작 계획서만 수정**한다. `index.html`, 실제 `.xlsx` 템플릿 및 자동 생성 코드는 **제작 승인 후 index.html 초기 구현을 수행한다**.
- 후속 확인: Git diff에 미커밋 파일을 포함할지, 증적 이미지 첨부를 Excel 생성 시점에 허용할지, 결재 직책별 후보 관리 방식.
