# 벨라의 팀 일정 업무 OS 제작 계획서

[기획서](prd.md) · 구현 파일 `index.html`

## 1. 만드는 순서

| 단계 | 할 일 | 확인 항목 |
|---|---|---|
| 화면 골격 | 오늘 날짜, 담당자 선택, 내 마감 임박 목록, 팀 월간 타임라인을 배치한다. | 담당자를 바꿔도 팀 일정이 모두 보인다. |
| 날짜 계산 | 인증서 30일, 사업 품의 14일, 매월 둘째 수요일을 계산한다. | 월·연도 경계를 넘는 날짜와 월마다 다른 둘째 수요일이 올바르게 나온다. |
| 일정 편집 | 업무명, 유형, 담당자, 기준일, 상태, 메모를 입력받는다. | 필수 값이 비어 있으면 안내하고, 유효한 변경을 저장한다. |
| 예시와 저장 | 가상 일정 5건과 예시 지우기, JSON 백업·복원을 제공한다. | 예시 삭제 시 직접 추가한 일정은 남고, 백업을 불러오기 전에 확인한다. |
| 화면 점검 | 휴대폰 375px와 데스크톱에서 배치와 키보드 조작을 확인한다. | 가로 스크롤이나 잘린 내용이 없다. |

## 2. 저장 방식

브라우저의 `localStorage`에 `myos:team-schedule` 키 하나로 일정, 월별 정기 작업 상태, 담당자 선택과 데이터 형식 버전을 함께 저장한다. 저장이 막히면 열린 페이지에서 작업을 이어갈 수 있게 하고 그 상태를 표시한다.

백업 파일은 `team-schedule-backup-YYYYMMDD.json`으로 내려받는다. 복원할 때 데이터 형식을 확인한 뒤, 사용자 확인을 받아 현재 내용을 교체한다. 형식이 잘못된 파일을 가져오면 현재 일정은 유지한다.

## 3. 확인할 시나리오

1. 같은 달에 담당자 A와 B의 일정을 띄우고 ‘내 담당자’를 바꾼다. 양쪽 일정이 계속 표시되며 강조만 바뀌는지 확인한다.
2. 가짜 인증서 만료일을 2027-01-10으로 입력하면 교체 시작일이 2026-12-11인지 확인한다. 사업 착수일 2026-12-04의 승인 마감일은 2026-11-20이다.
3. 정기 작업이 2026년 11월에는 11일, 12월에는 9일에 표시되는지 확인한다. 11월에 완료 표시를 해도 12월 상태는 예정으로 남아야 한다.
4. 일정 추가 → 새로고침 → JSON 백업 → 일정 변경 → 백업 복원 순서로 확인한다.
