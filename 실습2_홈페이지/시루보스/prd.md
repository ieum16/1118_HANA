PRD는 무엇을, 누구를 위해, 왜 만들지 정리한 기획서입니다. `(가정)`은 아직 확정하지 않은 제안입니다.

## 1. 배경 · 문제
협업하는 다른 팀이 자동화랩에 어떤 업무를 제안할 수 있는지 쉽게 파악하도록 한다. 현재는 업무 제안의 범위와 전달 방식이 명확하지 않다고 가정한다. (가정)

## 2. 목표와 성공 기준
| 목표 | 성공 기준 · 측정 방법 |
|---|---|
| 팀 역할 이해 | 협업 팀 구성원 3명이 페이지를 본 뒤 팀 역할과 업무 예시 1개를 설명한다. (가정) |
| 자동화 업무 제안 유도 | 테스트 방문자 3명이 제안 버튼과 작성 항목을 찾을 수 있다. (가정) |
| 제안 품질 개선 | 업무명·빈도·소요 시간·불편·원하는 결과를 포함한 제안을 받을 수 있다. (가정) |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지의 답 | 기대 행동 |
|---|---|---|---|
| 협업하는 다른 팀 | 어떤 일을 자동화할 수 있고 어떻게 제안하는가 | 업무 카드·제안 예시·제안 양식 | 자동화가 필요한 업무 제안 |

## 4. 범위
이번 범위는 2명으로 구성된 자동화랩 소개, 업무 카드 3개, 도구 준비 중 카드, 자동화 제안 안내, 모바일 대응이다.
로그인·서버 접수·메일/캘린더 연동·실제 자동화 도구 구현은 후속 범위다. (가정)

## 5. 정보 구조 (메뉴)
| 메뉴 | 섹션 ID | 내용 |
|---|---|---|
| 팀 소개 | #intro | 팀 이름·한 줄 소개·팀원 2명·제안 버튼 |
| 하는 일 | #work | 엑셀 데이터 정리·메일 정리·일정 정리 및 알림 |
| 만든 도구 | #tools | 준비 중 카드 |
| 자동화 제안 | #suggest | 제안 대상·작성 항목·복사 버튼·전달 방법 |

## 6. 화면 구성
헤더(로고·메뉴) → 팀 소개와 ‘자동화 업무 제안하기’ 버튼 → 업무 카드 3개 → 만든 도구(준비 중) → 자동화 제안 → 푸터.
팀 소개의 버튼은 #suggest로 이동한다. (가정)

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 팀 이름: 자동화랩
- 제목: 반복 업무를 줄이는 도구를 만드는 팀
- 보조 문구: 엑셀, 메일, 일정에서 반복되는 일을 함께 살펴봅니다. 자동화가 필요한 업무를 제안해 주세요. (가정)
- 규모: 2명이 함께하는 자동화랩
- 버튼: 자동화 업무 제안하기

### 7-2. 업무 카드
| 제목 | 설명 | 제안 예시 |
|---|---|---|
| 엑셀 데이터 정리 | 반복되는 표 정리와 데이터 취합을 줄이는 도구를 만듭니다. | 매주 여러 표를 합치고 중복 항목을 정리해요. |
| 메일 정리 | 메일 분류와 필요한 내용 정리를 돕는 도구를 만듭니다. | 쌓인 메일에서 처리할 요청을 따로 모으고 싶어요. |
| 일정 정리 및 알림 | 흩어진 일정과 마감일을 정리하고 알림을 돕는 도구를 만듭니다. | 반복 일정과 마감일을 놓치지 않게 정리하고 싶어요. |

카드 설명과 제안 예시는 편집 초안이다. (가정) 실제 메일·일정 서비스 연결 기능이 제공되는 것처럼 표현하지 않는다.

### 7-3. 만든 도구
점선 카드 1개와 ‘준비 중’ 배지. 문구: ‘첫 번째 도구를 준비하고 있습니다. 반복되는 업무를 알려주시면 다음 도구의 아이디어가 됩니다.’ (가정)
가상의 도구·성과·이용자 수는 기재하지 않는다.

### 7-4. 자동화 제안
구현 초안: 아래 텍스트 양식을 ‘제안 양식 복사’ 버튼으로 복사하고, 지정 채널에 붙여 넣도록 안내한다. 전송·접수 기능은 없다. (가정)

```text
업무 이름:
현재 진행 방식:
반복 빈도:
한 번에 걸리는 시간:
가장 번거로운 부분:
자동화되면 원하는 결과:
```

개인정보·고객 정보·비밀번호·API 키를 적지 않도록 안내한다. 복사 실패 시 양식을 직접 선택해 복사할 수 있게 한다.

| 항목 | 값 |
|---|---|
| 제안 채널 | #자동화-제안 (예시·미확정) |
| 이메일 | team@example.com (예시·미확정) |
| 응답 시간 | 미정 · 별도 약속 문구 없음 |

채널과 이메일에는 ‘예시’ 표시를 붙이고 실제 접수 링크로 연결하지 않는다. 전달 경로는 공개 전에 확정한다.

## 9. 반응형 · 접근성
375px~1280px에서 가로 스크롤 없이 표시한다. 업무 카드는 데스크톱 3열·태블릿 2열·휴대폰 1열. 640px 미만에서는 햄버거 메뉴를 사용한다.
휴대폰 좌우 여백 16px, 키보드로 버튼·메뉴 사용 가능, 포커스 표시, 충분한 글자 대비, 이미지 대체 텍스트를 제공한다.

## 10. 기술 조건
index.html 하나에 CSS·JS를 포함하고 빌드·서버 없이 연다. 이미지는 images/에 둔다. 외부 의존은 선택적 글꼴 CDN으로 제한한다.
로고가 없으면 ‘자’ 글자의 임시 SVG를 쓴다. 파일 추가 시 이미지로 바뀌도록 구현한다. 복사 버튼은 실패 처리와 직접 복사 안내를 제공한다.

## 11. 제작 순서
기획 검토 → 로고 방향 선택 → 제작 승인 → HTML 제작 → 데스크톱·모바일 검토 → 제안 경로 확정.

## 12. 완료 기준

- [ ] 팀명·소개·2명 규모·업무 3개가 정확하다.
- [ ] 팀 소개 버튼이 자동화 제안 섹션으로 이동한다.
- [ ] 준비 중 카드가 표시된다.
- [ ] 제안 양식 복사와 실패 시 직접 복사가 가능하다.
- [ ] 예시 채널과 실제 접수 경로가 구분된다.
- [ ] 375px에서 가로 스크롤이 없고 모바일 메뉴가 동작한다.
