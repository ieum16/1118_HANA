# 네트워크 보안팀 홈페이지 제작 계획서

## 1. 만들 것
- 협업 부서와 신규 입사자를 위한 한 장짜리 팀 소개 페이지.
- PRD: prd.md. 홈페이지 제작은 사용자가 기획을 확인한 뒤 시작한다.

## 2. 파일 구조
```text
team-page/
├─ prd.md             기획서
├─ logo-prompt.md     로고 제작용 문구
├─ build-plan.md      제작 계획서
├─ index.html         제작 확인 후 만들 파일
└─ images/
   └─ logo.png        로고 준비 시 추가
```
기획 문서 3개와 images/logo.png, index.html이 준비되어 있다. 수업 저장소 제출 시에는 index.html과 images가 개인 실습2 폴더 바로 안에 있도록 정리한다.

## 3. 준비물 체크
| 준비물 | 상태 | 없을 때 |
|---|---|---|
| 로고 | images/logo.png 준비 완료: 방화벽 앞을 지키는 고양이 | 로딩 실패 시 ‘네’ 글자 임시 로고 사용 |
| 참고 이미지 | 없음으로 이해 | PRD 디자인 가이드 사용 |
| 문의 이메일 | 예시 | team@example.com을 텍스트로 표시 |
| 업무 목록 | 확인 | 방화벽·VPN·WAF·DDoS·WIPS·DNS·NAC |
| 요청 방법·FAQ | 가상 초안 | 기획 검토 시 수정 가능 |

## 4. 만드는 순서
| 단계 | 할 일 | 확인할 것 |
|---|---|---|
| 1 | 기획 검토와 제작 확인 | 열린 질문과 사용자 수정 사항 반영 |
| 2 | 헤더·6개 섹션·푸터 작성 | PRD의 화면 순서와 일치 |
| 3 | 검정·파랑 디자인 적용 | 색과 글자 대비 |
| 4 | 팀 소개와 이동 버튼 | 역할이 한눈에 읽힘 |
| 5 | 7개 업무 카드 | 업무별 설명과 요청 예시 |
| 6 | 요청 방법·FAQ | 가상의 설명임이 분명함 |
| 7 | 도구 준비 중 카드·문의 | 점선 테두리와 예시 이메일 |
| 8 | 모바일 메뉴·키보드 대응 | 조작 가능, 초점 표시 |
| 9 | 브라우저 확인 | 메뉴·모바일·로고 대체 표시 |

## 5. 섹션별 구현 메모
| 섹션 | 레이아웃 | 데스크톱 → 휴대폰 |
|---|---|---|
| 헤더 | 고정 메뉴, 로고와 팀 이름 | 메뉴 → 햄버거 버튼 |
| 팀 소개 | 큰 제목 + CSS 연결선 장식 | 2열 → 1열 |
| 하는 일 | 제목·설명·요청 예시 카드 7장 | 3열 → 2열 → 1열 |
| 요청 방법 | 번호가 붙은 3단계 안내 | 가로 → 세로 |
| FAQ | 기본 HTML details로 질문 펼치기 | 1열 유지 |
| 도구 | 점선 준비 중 카드 | 화면 너비에 맞춤 |
| 문의 | 예시 이메일과 수업용 안내 | 1열 |

보안 상황을 실시간으로 보여 주는 듯한 수치나 경보는 만들지 않는다. CSS·JS는 index.html 안에 넣고 로고 외 외부 자산 의존을 두지 않는다.

## 6. 확인 방법
- index.html을 브라우저에서 열어 1280px과 375px 너비에서 확인한다.
- 메뉴와 소개 영역 버튼이 알맞은 섹션으로 이동하는지 확인한다.
- 7개 카드 내용이 기획서와 같은지 확인한다.
- 휴대폰 메뉴 열기·닫기와 FAQ 펼치기를 확인한다.
- 키보드로 버튼과 링크를 선택할 수 있는지 확인한다.
- 로고가 없어도 임시 로고가 보이고, 파일을 추가하면 교체되는지 확인한다.
- PRD 12번 완료 기준으로 최종 점검한다.
- 실제로 확인하지 못한 항목은 확인하지 못했다고 알린다.

## 7. 만든 뒤 고치기 예시
- ‘업무 카드 설명을 더 쉽게 바꿔 줘.’
- ‘파란색을 더 밝게 바꿔 줘.’
- ‘요청 방법에 준비물 안내를 추가해 줘.’
- ‘도구가 생겼으니 준비 중 카드를 링크로 바꿔 줘.’

## 8. 제작 결과
- 큰 밈 고양이 로고와 차분한 문구를 사용했다. 고양이 말투는 사용하지 않았다.
- 업무 7개에 자세한 설명·요청 예시·준비물을 넣고 펼치기·접기를 구현했다.
- index.html을 더블클릭해 열 수 있으며 서버·설치·로그인이 필요 없다.
- 로컬 브라우저에서 데스크톱·375px 화면과 모바일 메뉴·FAQ를 확인했다.
- 공개 배포와 GitHub 업로드는 별도 단계다.

## 9. Superdesign 참고 디자인 수정
- 참고: https://superdesign.dev/ 의 Neo-Brutalism Style.
- 밝은 바탕, 파란 버튼, 노란 강조, 굵은 테두리와 단단한 그림자를 적용했다.
- 원본 고양이 로고와 업무 내용, 메뉴·FAQ 기능은 유지했다.
- 개인 실습2 폴더와 team-page 작업 폴더의 index.html을 동일하게 수정했다.
- 데스크톱·375px 화면과 메뉴·FAQ를 확인하고 로컬 미리보기를 열었다.
- 사용자 승인 후 개인 GitHub에 갱신했고 기존 Vercel 주소에서 새 디자인 반영을 확인했다. 수업 제출용 screenshot.png도 새 첫 화면으로 교체했다.
