> PRD는 무엇을, 누구를 위해, 왜 만들지 정리한 기획서입니다. 이 페이지는 가상의 팀을 소개하는 수업용 페이지입니다.

## 1. 배경 · 문제
- 협업 부서와 신규 입사자가 보안 장비별 역할과 요청 방법을 한눈에 알 수 있는 페이지가 필요하다.
- 업무 설명과 요청 준비물을 한곳에 모아 처음 문의할 때의 어려움을 줄인다. 현재의 문의 방식과 어려움은 인터뷰에서 확인하지 않았으므로 가정이다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (제작 후 확인할 제안 기준) |
|---|---|
| 팀 역할 이해 | 처음 보는 사람이 1분 안에 팀의 주요 업무 3가지를 설명한다 |
| 요청 방법 이해 | 방문자가 원하는 업무의 요청 예시와 준비물을 찾는다 |
| 쉽게 읽기 | 데스크톱과 휴대폰에서 메뉴와 업무 카드가 읽힌다 |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줘야 할 답 | 기대 행동 |
|---|---|---|---|
| 협업 부서 | 어떤 보안 업무를 요청할 수 있나? | 업무별 역할, 요청 예시, 준비물 | 요청 내용을 정리한다 |
| 신규 입사자 | 이 팀은 무슨 일을 하나? | 쉬운 업무 설명과 용어 풀이 | 팀 역할과 요청 흐름을 이해한다 |

## 4. 범위
**이번에 만드는 것**
- 한 장짜리 소개 페이지: 팀 소개, 업무 7개, 요청 방법, FAQ, 도구 준비 중 카드, 문의.
- 모바일 메뉴와 섹션 이동.

**이번에 만들지 않는 것**
- 로그인, 실제 신청 접수, 장비 연결, 실시간 보안 현황, 공격 탐지 기능.
- 고객 정보, 사내 주소, 실제 장비 구성, 실제 보안 정책.

## 7. 콘텐츠 상세
### 7-1. 한 줄 소개
- 팀 이름: 네트워크 보안팀
- 제목: 안전한 연결을 만드는 팀.
- 첫 화면: 두 번째 밈 고양이 로고를 크게 배치. ‘~냥’ 같은 말투는 사용하지 않는다.
- 보조 문구 (제작 반영): 연결은 유연하게, 보안은 빈틈없이. 네트워크의 경계부터 모든 접속의 순간까지, 네트워크 보안팀이 함께합니다.
- 보조 문구: 방화벽부터 VPN, WAF, DDoS, WIPS, DNS, NAC까지. 네트워크 보안 업무와 요청 방법을 한곳에서 확인하세요.
- 버튼: 하는 일 보기 / 요청 방법 보기
- 팀 규모와 소속: 미정이며 표시하지 않는다.

### 7-2. 업무 카드
아래 설명과 요청 예시는 사용자에게 받은 업무 목록을 바탕으로 작성한 가상의 초안이다. DNS는 도메인 이름 관리 역할로 가정하며 실제 담당 범위는 확인이 필요하다.

| # | 제목 | 설명 | 요청 예시 |
|---|---|---|---|
| 1 | 방화벽 | 네트워크 연결을 허용하거나 제한하는 정책을 관리합니다. | 테스트 서비스 연결 검토 |
| 2 | VPN | 외부에서도 안전하게 업무 환경에 접속하도록 돕습니다. | 원격 접속 이용 방법 문의 |
| 3 | WAF | 웹 요청을 살펴보고 웹 서비스를 겨냥한 공격을 차단합니다. | 신규 웹 서비스 보호 검토 |
| 4 | DDoS | 대량의 트래픽으로 서비스가 중단되는 공격에 대응합니다. | 서비스 보호 적용 문의 |
| 5 | WIPS | 무선 네트워크의 비인가 접속과 위협에 대응합니다. | 무선 접속 보안 검토 |
| 6 | DNS | 도메인 이름과 네트워크 주소를 연결하는 설정을 관리합니다. | 예시 도메인 설정 변경 문의 |
| 7 | NAC | 네트워크에 접속하는 기기의 허용 여부와 보안 상태를 확인합니다. | 테스트 기기 접속 절차 문의 |

### 7-3. 요청 방법 (가상의 예시)
1. 업무 선택: 7개 업무 카드에서 가까운 항목을 찾는다.
2. 내용 정리: 요청 목적, 필요한 기간, 영향 범위를 정리한다. 페이지에는 입력하지 않는다.
3. 문의 안내 확인: 예시 이메일을 보고 요청 흐름을 이해한다. 실제 접수 기능은 없다.

### 7-4. 자주 묻는 질문 (가정)
| 질문 | 답변 초안 |
|---|---|
| 어떤 업무인지 잘 모르겠어요. | 업무 카드의 요청 예시를 먼저 확인하세요. |
| 요청 전에 무엇을 정리하나요? | 목적, 필요한 기간, 영향 범위를 정리하면 상담에 도움이 됩니다. |
| 이 페이지에서 바로 신청할 수 있나요? | 수업용 소개 페이지로 실제 신청은 접수하지 않습니다. |
| 긴급 장애도 여기로 접수하나요? | 이 페이지는 실제 대응 채널이 아닙니다. 실제 상황에서는 소속 조직의 공식 절차를 따르세요. |

### 7-5. 문의
| 항목 | 값 |
|---|---|
| 이메일 | team@example.com (예시 텍스트) |
| 안내 | 가상의 팀 소개 페이지이며 실제 요청을 접수하지 않습니다 |
| 응답 시간 | 정해진 운영 시간이 없으므로 표시하지 않음 |

## 9. 반응형 · 접근성
- 375px 휴대폰과 1280px 데스크톱에서 가로 스크롤 없이 표시한다.
- 업무 카드: 데스크톱 3열 → 태블릿 2열 → 휴대폰 1열.
- 640px 아래에서는 메뉴를 햄버거 버튼으로 바꾼다.
- 키보드로 메뉴와 버튼을 조작하고 선택 위치를 확인할 수 있어야 한다.
- 이미지 대체 텍스트, 충분한 글자 대비, 움직임 감소 설정을 고려한다.

## 10. 기술 조건
- index.html 한 파일에 CSS와 JavaScript를 포함하고 더블클릭으로 연다.
- 로고는 선택 이미지 파일이다. 없으면 팀 이름 첫 글자 ‘네’로 임시 로고를 만든다.
- 로고 파일을 추가한 뒤 새로고침하면 정식 로고가 표시되도록 구현한다.
- 서버, 로그인, 외부 전송, 입력 폼, 분석 도구 없이 동작한다.
- 사용자 요청에 따라 현재 team-page 폴더에 산출물을 저장한다.
- 수업 저장소 제출 시 index.html이 개인 실습2 폴더 바로 안에 있도록 정리한다.

## 13. 열린 질문
- 로고는 후속 요청에 따라 방화벽을 지키는 고양이로 제작했다. 참고 화면은 없는 것으로 가정한다.

- DNS 업무 설명을 도메인 이름 관리로 표현해도 되는가?
- 가상의 요청 단계와 FAQ를 이대로 사용할 것인가?

## 14. 제작 시 확정 사항과 확인 결과
- 사용자가 홈페이지 제작을 승인했고, 첫 화면은 로고 중심으로 선택했다.
- 업무 설명은 자세하게 작성한다. index.html의 7개 업무마다 설명·요청 예시·준비물 3개를 담았다.
- 준비물은 기본적으로 펼쳐 표시하며 카드 제목을 눌러 접을 수 있다.
- 로컬 브라우저에서 데스크톱과 375px 휴대폰 화면을 확인했다. 고양이 이미지 로딩, 업무 7개 표시, 모바일 가로 넘침 없음, 메뉴 열기와 FAQ 이동 후 메뉴 닫힘, FAQ 답변 펼치기를 확인했다.
- JavaScript 문법 검사 통과. 브라우저에서 수집된 콘솔 오류 없음.
- 로고 파일 누락 시의 대체 표시는 구현했으나 직접 파일을 제거하는 확인은 하지 않았다.
- 실제 배포와 GitHub 업로드는 진행하지 않았다.

## 15. Superdesign 참고 디자인 적용
- 이전 버전은 수업 GitHub와 Vercel에 배포 완료. 이 항목은 이후 로컬 디자인 수정 내용이다.
- 참고: https://superdesign.dev/ 의 ‘Neo-Brutalism Style’ (Zhou Jason). 화면을 직접 확인하고 큰 제목·굵은 테두리·단단한 그림자·스티커형 장식 원칙을 참고했다.
- 고양이 밈 로고는 교체하지 않았다. 파란 격자 패널에 배치하고 노란 라벨과 제목 밑줄로 강조했다.
- 업무 7개와 요청 준비물, FAQ, 모바일 메뉴 기능을 유지했다.
- 1280px와 375px에서 가로 넘침 없음. 모바일 메뉴 열기·링크 이동 후 닫힘·FAQ 펼치기·로고 표시 확인. 콘솔 오류 없음.
- 수정본을 개인 GitHub TGMinS/team-page에 반영하고, https://team-page-gamma-olive.vercel.app/ 에서 밝은 배경·NETWORK GUARD 라벨·고양이 로고 표시를 확인했다. 새 첫 화면으로 screenshot.png도 갱신했다.
