# 마케팅플랫폼팀 팀 소개 페이지 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.1 |
| 작성일 | 2026-11-19 |
| 작성 주체 | 마케팅플랫폼팀 · 대화 기반 초안 |
| 관련 문서 | logo-prompt.md, build-plan.md |

PRD는 누구를 위해 무엇을 만들지 정리한 제품 요구사항 문서입니다. `(가정)`은 사용자 확인이 필요한 제안입니다.

## 1. 배경과 문제

현업부서가 마케팅플랫폼팀의 담당 업무, 문의할 담당자, 필요한 대시보드를 한곳에서 찾도록 팀 소개 페이지를 만든다. 정보가 흩어져 있어 찾기 어렵다는 상황을 출발점으로 삼는다. (가정)

## 2. 목표와 성공 기준

| 목표 | 성공 기준 |
|---|---|
| 팀 업무 이해 | 현업 사용자 3명이 페이지를 보고 주요 업무 4가지를 찾는다. (가정) |
| 담당자와 문의 경로 찾기 | 현업 사용자가 원하는 업무의 문의 경로를 1분 안에 찾는다. 실제 담당자 정보 등록 후 검증한다. (가정) |
| 대시보드 접근 | 두 대시보드의 용도를 구분하고 연결 주소 등록 후 각각 열 수 있다. |

## 3. 대상 사용자

| 대상 | 궁금한 것 | 제공할 정보 | 기대 행동 |
|---|---|---|---|
| 현업부서 | 어떤 업무를 요청할 수 있는가 | 업무 4종과 요청 예시 | 적절한 담당자에게 문의 |
| 현업부서 | 마케팅 실행 현황과 피로도를 어디서 보는가 | 대시보드 용도와 연결 상태 | 필요한 대시보드 사용 |

## 4. 범위

- 반응형 한 장짜리 팀 소개 홈페이지와 메뉴 7개를 제작한다.
- 팀 소개, 업무 카드, 대시보드 카드, 담당자·문의, 일하는 방식, FAQ, 공지를 제공한다.
- 이번 제작 범위는 정적 소개 페이지이며, 실제 대시보드는 제공받은 주소로 연결한다. (가정)
- 실제 담당자 배정, 문의 접수 시스템, 마케팅 지표 산출 및 데이터 연동은 별도 요구사항으로 남긴다. (가정)

## 5. 정보 구조

| 메뉴 | 섹션 ID | 내용 |
|---|---|---|
| 팀 소개 | intro | 한 줄 소개, 팀원 8명, 주요 이동 버튼 |
| 하는 일 | work | 시스템 기획, 시스템 운영, 데이터 정비, 손님관리 프로세스 구축 |
| 대시보드 | dashboards | 마케팅 실행 건수·대상 손님 수, 피로도 |
| 담당자·문의 | contact | 업무별 문의 경로와 담당자 등록 상태 |
| 일하는 방식 | process | 요청부터 개선까지의 흐름 초안 |
| FAQ | faq | 문의 전 자주 확인할 내용 초안 |
| 공지 | notices | 공지 등록 준비 상태 |

## 6. 화면 구성

고정 헤더 → 팀 소개 → 하는 일 → 대시보드 → 담당자·문의 → 일하는 방식 → FAQ → 공지 → 푸터 순서로 구성한다. (가정)

## 7. 콘텐츠 상세

### 한 줄 소개

- 팀 이름은 마케팅플랫폼팀이다. 팀원은 8명이다.
- 소개 문구는 “시스템을 기획·운영하고, 데이터와 손님관리 프로세스를 정비하는 마케팅플랫폼팀입니다.”로 제안한다. (가정)
- 보조 문구는 “반복 업무를 줄이는 대시보드로 현업의 업무를 돕습니다.”로 제안한다. (가정)
- 주요 버튼은 “대시보드 보기”, “담당 업무·문의 찾기”로 구성한다. (가정)

### 업무 카드

| 제목 | 설명 초안 (가정) | 요청 예시 (가정) |
|---|---|---|
| 시스템 기획 | 현업의 요구를 정리해 시스템 개선 방향과 기능을 설계합니다. | 새로운 업무 기능이 필요해요. |
| 시스템 운영 | 시스템 이용 과정의 문의와 운영 개선사항을 살펴봅니다. | 시스템 이용 중 확인할 사항이 있어요. |
| 데이터 정비 | 마케팅 업무에 필요한 데이터의 기준과 품질을 정비합니다. | 데이터 기준이나 값 확인이 필요해요. |
| 손님관리 프로세스 구축 | 손님관리 업무의 흐름과 기준을 정리합니다. | 손님관리 절차를 정리하고 싶어요. |

### 대시보드

| 제목 | 용도 | 초기 표시 |
|---|---|---|
| 마케팅 실행 현황 | 마케팅 실행 건수와 대상 손님 수 확인 | 연결 준비 중 |
| 피로도 | 마케팅 접촉에 따른 손님 피로도 확인 (가정) | 연결 준비 중 |

두 대시보드는 사용자가 제시한 항목이다. 주소가 제공되면 연결한다. 초기에는 실제 수치나 가짜 실행 링크를 넣지 않고, 점선 카드에 “연결 준비 중”을 표시한다. 피로도의 정의·기준·집계 기간은 확인이 필요하다.

### 담당자·문의

업무 4종별로 “담당자 등록 예정”을 표시한다. (가정) 문의 경로는 “문의 채널 등록 예정”으로 표시한다. (가정) 팀원 수 8명만 공개하며, 담당자 정보와 응답 시간은 제공받은 뒤 반영한다.

### 일하는 방식, FAQ, 공지

- 일하는 방식은 “요청 내용 확인 → 담당 업무 검토 → 진행·결과 안내 → 개선사항 반영”으로 제안한다. (가정)
- FAQ 초안은 “어떤 업무를 문의할 수 있나요?”, “대시보드는 어디서 사용하나요?”, “문의할 때 무엇을 준비하나요?”로 구성한다. (가정)
- 문의 준비사항으로 업무 목적, 현재 상황, 원하는 결과를 제안한다. (가정)
- 공지는 “공지 준비 중” 카드로 표시한다. (가정)

## 8. 디자인 가이드

| 항목 | 값 |
|---|---|
| 메인 색 | 초록 `#176B4B` (색상 코드 가정) |
| 보조 색 | 옅은 초록 `#EEF6F1` (가정) |
| 본문 색 | 짙은 회녹색 `#1E3028` (가정) |
| 배경 | 옅은 초록 바탕 `#F0F5E9`, 메인 영역 `#FCFDF7` |
| 분위기 | 차분하고 전문적인 |
| 글꼴 | Pretendard, 시스템 기본 글꼴 대체 (가정) |
| 카드 | 크게 둥근 모서리와 짙은 회녹색 2px 테두리 |
| 로고 | 현재 없음. 초기에는 팀 이름과 첫 글자 기반 임시 로고 사용 (가정) |
| 참고 디자인 | 사용자가 제공한 다운로드.jpg의 둥근 메뉴, 큰 프레임, 좌우 분할 구성을 참고 |

상단은 캡슐 형태의 메뉴로 구성한다. 메인 영역은 둥근 큰 프레임 안에서 왼쪽 업무 안내 패널과 오른쪽 팀 소개·버튼을 세로선으로 구분한다. 참고 화면의 이미지 영역은 팀 업무로 바로 이동할 수 있는 안내 패널로 구성한다. 버튼은 둥근 캡슐 형태로 통일한다.

## 9. 반응형과 접근성

- 375px 휴대폰부터 1280px 데스크톱까지 가로 스크롤 없이 표시한다.
- 업무 카드는 데스크톱 4열, 태블릿 2열, 휴대폰 1열로 구성한다.
- 640px 미만에서는 햄버거 메뉴를 사용하고 휴대폰 좌우 여백은 16px로 둔다.
- 휴대폰에서는 메인 소개·버튼을 위에, 업무 안내 패널을 아래에 배치하고 가로선으로 구분한다.
- 메뉴와 버튼은 키보드로 조작 가능하게 하며 포커스를 표시한다.
- 고정 헤더가 이동한 섹션 제목을 가리지 않도록 한다.
- 글자 대비, 이미지 대체 텍스트, 메뉴의 펼침 상태를 제공한다.

## 10. 기술 조건

- CSS와 JavaScript를 포함한 index.html 한 장으로 제작한다.
- 빌드 도구 없이 파일을 브라우저로 열 수 있게 한다.
- 실제 로고는 images/logo.png로 두고 파일이 없으면 임시 로고를 표시한다.
- 참고 이미지가 제공되면 images/reference.png를 검토해 반영한다.
