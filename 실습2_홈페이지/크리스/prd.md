# DT팀 업무 포털 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | 제작본 v0.3 — CRT 터미널 디자인 반영 |
| 작성일 | 2026-11-19 |
| 작성 대상 | DT팀 |
| 관련 문서 | logo-prompt.md, build-plan.md |

PRD는 무엇을, 누구를 위해, 왜 만드는지 정리한 제품 요구사항 문서입니다.

## 1. 배경 · 문제
DT팀은 그룹의 인프라 관리, 계약 관리, 프로그램 운영과 장애 대응, 영업 및 운용 딜러 지원을 담당한다. 폭넓은 업무 중 반복 업무를 찾아 자동화하는 것이 최근 핵심 과제다. 직원이 필요한 현황을 빠르게 확인하고 담당 업무에 맞는 정보에 접근할 수 있는 포털을 만든다.

## 2. 목표와 성공 기준
| 목표 | 성공 기준 |
|---|---|
| 장애 상황 즉시 인지 | 장애가 있으면 최초 화면에서 스크롤 없이 서비스명·영향·대응 상태 확인 |
| 간결한 업무 확인 | 사용자별 핵심 현황을 10초 내 파악하는 것을 검토 목표로 설정 (가정) |
| 역할별 화면 구분 | 일반 직원·지정 관리자·DT팀 전환 시 권한표에 맞게 메뉴·내용·변경 기능 표시 |
| 계약 만료 사전 확인 | 권한 있는 사용자만 만료 예정 계약과 남은 일수 확인 |
| 자동화 기회 수집 | 반복 업무 제안을 시안에서 등록하고 목록으로 확인 |

## 3. 대상 사용자
| 대상 | 필요한 정보 | 기대 행동 |
|---|---|---|
| 그룹 내 모든 직원 | 공통 장애 알림, 전광판 현황, 자동화 제안 | 현황 확인 및 개선 제안 |
| 지정 관리자 | 공통 정보와 계약 현황 | 만료·예산 분류 확인 |
| DT팀 | 전체 현황 및 관리 기능 | 인프라·계약 변경, 장애 공지 관리 |
| 영업·운용 등 업무 담당자 | 자신의 업무와 관련 있는 영향 정보 | 필요한 정보만 빠르게 확인 |

## 4. 범위
### 이번에 만드는 것
- CSS·JS를 포함하는 index.html 한 장으로 실행되는 반응형 시안.
- 직원 / 관리자 / DT 역할 전환. 상단 업무 필터는 제공하지 않는다.
- 최상단 공통 장애 알림, 핵심 상태 요약, 메뉴 이동.
- 한 전광판 카드에 계단측·벽면·천장 상태를 묶고 DT팀의 개별 등록·수정·삭제 기능을 제공한다.
- 전광판 컨트롤러 버튼은 https://example.com/ 예시 주소를 새 탭으로 연다.
- 권한별 계약 조회와 DT팀의 등록·수정·삭제 체험.
- 자동화 제안 등록 체험, 프로그램 운영 준비 중 영역.
- 가상 데이터 및 브라우저 내 저장. 브라우저 초기화·백업 기능 제공 (가정).

### 실제 운영으로 확장할 때 구현할 것
- 사내 로그인/SSO, 서버의 역할·부서·업무 권한 검사, 데이터베이스와 API.
- 서버에서 비인가 계약 데이터 자체를 반환하지 않는 처리.
- 공통 데이터 공유, 감사 이력, 실제 모니터링 연동, 장애 공지 배포.
- 시안의 역할 선택기는 화면 검토용이며 실제 접근 통제를 제공하지 않는다. 실데이터는 넣지 않는다.

## 5. 정보 구조

|---|---|---|
| 메인·장애 공지 | #overview | 장애 알림, 핵심 요약, 업무 바로가기, DT팀 한 줄 소개 |
| 인프라 현황 | #infrastructure | 전광판: 계단측 / 벽면 / 천장 |

| 프로그램 운영 | #operations | 점선 테두리와 준비 중 배지, 세부 기능 추후 결정 |
| 자동화 제안 | #automation | 반복 업무, 불편, 개선 아이디어 접수 |

## 6. 화면 구성 (위에서 아래로)
1. 고정 헤더: DT 로고, 메뉴, 사용자 역할 선택(직원 / 관리자 / DT).
2. 활성 장애 알림: 첫 콘텐츠로 배치. 짧은 제목과 서비스명·영향·대응 상태·최종 갱신, 상세 보기.
3. 짧은 소개: “운영은 안정적으로, 업무는 더 간결하게.”
4. 권한에 맞는 핵심 요약: 전광판 상태, 진행 중 장애, 만료 예정 계약(권한 보유 시).
5. 인프라 현황 → 계약 관리(권한 보유 시) → 프로그램 운영 준비 중 → 자동화 제안.
6. 푸터: DT팀 업무 영역과 예시 문의 채널.

정상 상태에서는 작은 정상 운영 안내를 표시한다. 장애 상태를 초록색 요약에 섞지 않고 붉은 배경·아이콘·문구로 구분한다. 모바일에서도 장애 알림이 소개·통계보다 먼저 보인다.

## 7. 콘텐츠 상세
### 7-1. DT팀 소개
그룹의 인프라와 프로그램을 안정적으로 운영하고, 계약 관리와 영업·운용 지원을 연결합니다. 반복 업무의 자동화 기회를 찾아 더 효율적인 업무 환경을 만듭니다.

### 7-2. 인프라 데이터
| 항목 | 값 |
|---|---|
| 자산명 | 가상 전광판 이름 |
| 위치 구분 | 계단측 / 벽면 / 천장 |
| 운영 상태 | 정상 / 점검 중 / 장애 (가정) |
| 담당 | 가상 닉네임 (가정) |
| 최종 갱신·메모 | 시안용 시간과 짧은 설명 (가정) |

### 7-3. 계약 데이터
| 항목 | 값 |
|---|---|
| 계약명 | 가상 계약 이름 (가정) |
| 계약 종류 | 단말기 / 데이터 / 프로그램 라이선스 |
| 업체명 | 가상 업체 |
| 계약 기간 | 시작일~종료일 |
| 만료일 | 종료일과 동일한 단일 값에서 표시·계산 |
| 예산 구분 | 경비 / 자본 |
| 담당·상태 | 가상 담당, 유효/만료 예정/만료 (가정) |

만료 예정 기준은 30일 이내로 가정하고 만료 계약은 별도로 표시한다. 날짜는 한국 날짜 기준으로 계산한다. 시작일이 종료일보다 늦은 입력은 막는다. 금액·계약 문서 첨부는 이번 시안에 포함하지 않는다.

### 7-4. 권한표
| 기능 | 일반 직원 | 지정 관리자 | DT팀 |
|---|---|---|---|
| 메인·장애 조회 | 가능 | 가능 | 가능 |
| 인프라 조회 | 가능 | 가능 | 가능 |
| 인프라 등록·수정·삭제 | 불가 | 불가 | 가능 |
| 계약 조회 | 불가 | 가능 | 가능 |
| 계약 등록·수정·삭제 | 불가 | 불가 | 가능 |
| 장애 공지 등록·수정·해제 | 불가 | 불가 | 가능 (가정) |
| 자동화 제안 등록 | 가능 (가정) | 가능 (가정) | 가능 (가정) |

상단 업무 필터 없이 역할별로 정보를 표시한다. 전 직원 공통 장애는 모든 역할에서 표시한다. 계약 권한이 없으면 계약 요약 숫자·검색 결과·상세도 화면에 노출하지 않는다. 제안 공개 범위는 시안에서 모든 역할에 공개하는 것으로 가정한다.

### 7-5. 장애 및 자동화 제안
- 장애: 서비스명, 상태(확인 중/조치 중/복구 완료), 영향, 발생 시각, 마지막 갱신, 안내 문구 (필드 구성은 가정).
- 복구 완료 시 진행 중 장애 수에서 제외하고 완료 이력으로 표시 (가정).
- 자동화 제안: 제목, 관련 업무, 반복되는 불편, 기대 효과, 접수 상태 (가정).
- 문의는 team@example.com 같은 예시 값만 사용한다.

## 9. 반응형 · 접근성
- 데스크톱과 375px 휴대폰 폭에서 검토. 가로 스크롤 없음.
- 640px 미만에서는 햄버거 메뉴. 좁은 화면의 표는 카드로 변환.
- 요약 카드 3열 → 2열 → 1열. 휴대폰 좌우 여백 16px.
- 메뉴는 각 섹션으로 부드럽게 이동하며 고정 헤더에 제목이 가려지지 않게 한다.
- 장애는 색뿐 아니라 텍스트와 아이콘으로 전달. 키보드 조작과 명확한 초점 표시.
- 폼 라벨, 오류 안내, 빈 목록 안내, 삭제 전 확인 제공.
- 장식용 스캔라인은 클릭을 가로막지 않는다. 동작 줄이기 설정에서는 커서·상태 점 애니메이션을 끈다.

## 10. 기술 조건
- index.html에 CSS·JS 포함. 빌드 없이 로컬에서 열기.
- 입력 내용은 HTML로 삽입하지 않고 텍스트로 표시.
- 브라우저 저장 실패 시 현재 세션에서 사용 가능하도록 안내 (가정).
- 가상 데이터만 포함하며 실제 회사 내부 주소·계약·연락처는 사용하지 않는다.

## 12. 완료 기준
- [ ] 첫 화면에서 활성 장애를 즉시 확인한다.
- [ ] 일반 직원에게 계약 메뉴·내용·요약이 보이지 않는다.

- [ ] 공통 장애가 모든 역할에 표시된다.
- [ ] 전광판 통합 카드와 새 탭으로 열리는 예시 컨트롤러 버튼을 제공한다.
