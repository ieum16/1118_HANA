## 1. 배경과 문제

새 팀원에게 브릿지팀이 왜 고객 문의를 살피는지, 반복되는 문의를 발견했을 때 어떻게 공유하는지 안내할 페이지가 필요하다.

## 2. 목표와 성공 기준

| 목표 | 확인 방법 |
|---|---|
| 새 팀원이 브릿지팀의 역할을 이해한다 | 페이지를 본 뒤 브릿지팀이 하는 일을 한 문장으로 설명할 수 있다. |
| 새 팀원이 반복 문의를 공유할 수 있다 | 예시를 보고 어떤 내용을 정리해 어디로 공유할지 설명할 수 있다. |

## 3. 대상 사용자

새 팀원. 팀의 역할과 주요 업무를 파악하고, 반복되는 고객 문의를 발견하면 브릿지팀에 공유할 방법을 찾는다.

## 4. 범위

팀 소개, 업무 카드 세 개, 반복 문의를 정리하는 예시와 공유 안내를 한 페이지에 담는다. 문의 공유는 안내와 복사용 예시 문구로 구성한다.

## 5. 정보 구조

| 메뉴 | 섹션 ID | 내용 |
|---|---|---|
| 팀 소개 | `#intro` | 팀 이름과 한 줄 소개 |
| 하는 일 | `#work` | 문의 분류, 반복 문의 원인 분석, 개선안 제안 |
| 문의 공유 | `#contact` | 공유할 항목, 작성 예시, 채널 안내 |

## 6. 화면 구성

상단 메뉴 → 팀 소개 → 업무 카드 세 개 → 문의 공유.

## 7. 콘텐츠 상세

### 팀 소개

- 제목은 **브릿지팀**으로 표기한다.
- 한 줄 소개는 **고객 문의를 분석해 서비스 개선점을 찾는 팀**으로 쓴다.
- `반복 문의 공유하기` 버튼을 누르면 문의 공유 섹션으로 이동한다.

### 하는 일

| 카드 | 설명 | 예시 |
|---|---|---|
| 고객 문의 유형 분류 | 비슷한 문의를 주제별로 묶어 자주 나오는 문제를 찾는다. | 배송 상태 확인과 반품 접수 문의를 유형별로 정리한다. |
| 반복 문의 원인 분석 | 여러 문의에서 공통으로 고객이 막히는 화면이나 단계를 찾는다. | 배송 조회 버튼을 찾기 어렵다는 문의가 어느 화면에 집중되는지 확인한다. |
| 서비스 개선안 제안 | 분석 결과를 바탕으로 관련 팀과 화면이나 안내 문구의 개선점을 논의한다. | 주문 상세 화면에서 배송 조회 버튼이 더 잘 보이는 위치를 제안한다. |

### 문의 공유

- 문의 주제, 발생 화면이나 단계, 반복 빈도나 기간을 정리한다.
- 가상 예시는 “배송 조회 버튼 위치 문의가 지난주에 세 번 들어왔어요. 모두 주문 상세 화면에서 버튼을 찾지 못한 사례였어요.”를 사용한다.
- 공유 채널은 `#브릿지팀-문의`를 예시로 표시한다 (가정). 실제 채널이 확정되면 이름과 링크를 반영한다.
- 예시와 공유 양식에는 고객 이름, 연락처, 주문번호 없이 상황을 요약하도록 안내한다.

| 참고 이미지 | 제공 시 `images/reference.png` |

## 9. 반응형과 접근성

- 375px 모바일과 1280px 데스크톱에서 가로 스크롤 없이 읽을 수 있게 한다.
- 업무 카드는 데스크톱 3열, 태블릿 2열, 모바일 1열로 배치한다.
- 640px 미만에서는 접이식 메뉴를 사용한다. 키보드로 메뉴를 열고 항목에 접근할 수 있도록 한다.
- 메뉴와 버튼의 초점 상태를 표시하고, 글자와 배경 대비를 확보한다.

## 10. 기술 조건

CSS와 JavaScript를 포함한 `index.html` 한 파일로 구현한다. 브라우저에서 파일을 직접 열 수 있게 한다.

## 11. 일정

기획 초안 확인 → 로고 반영 또는 글자 로고 선택 → HTML 제작 → 브라우저 검토.
