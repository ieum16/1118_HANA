# 데이터마케팅팀 캠페인 웹앱 제작 계획서

## 1. 만들 것

캠페인 기획부터 타깃 설정, 푸시 메시지, 예정 일정과 성과 시뮬레이션을 이어서 처리하는 로컬 웹앱을 만듭니다.
사용자가 지정한 team-page 폴더를 사용합니다.

## 2. 파일 구성

- prd.md · 요구사항과 계산·저장 기준
- logo-prompt.md · 로고 제작 프롬프트
- build-plan.md · 이 제작 계획서
- index.html · 구현 단계에서 만들 앱
- images/logo.png · 로고를 제공하면 적용할 이미지

## 3. 준비 상태

| 항목 | 상태 | 초기 구현 방법 |
|---|---|---|
| 팀 이름·소개 | 확정 | 데이터마케팅팀 · 고객 데이터를 분석해 마케팅 성과를 높이는 팀 |
| 사용자·업무 흐름 | 확정 | 담당자·리더·협업 부서, 캠페인 준비와 조회 |
| 타깃 조건 종류 | 확정 | 연령대·최근 접속일·이용 빈도·보유 금융상품 |
| 색·분위기 | 확정 | #008485, #E90061, #B5B5B5 · 전문적인 대시보드 |
| 구간·전환율·글자 수 | PRD에 가정 표시 | 편집 가능한 예시로 구현 |
| 로고·참고 이미지 | 사용자 제공 전 | 글자 로고와 확정한 색으로 구현 |

## 4. 만드는 순서

| 단계 | 작업 | 확인 |
|---|---|---|
| 1 | 메뉴·기획·타깃·메시지·성과 요약 화면 구성 | 한국어 업무 흐름과 정보 위계 |
| 2 | 가상 고객 자료와 공통 타깃 필터 구현 | 조건 결합, 중복 없는 대상 수 |
| 3 | 클릭·앱 방문 계산과 요약 그래픽 | 최종 단계 반올림과 숫자 예제 |
| 4 | 푸시 미리보기와 날짜·시각 입력 | 글자 수, 유효 일정, 한국 시간 |
| 5 | 캠페인 계획 저장·수정·일정순 조회 | 같은 계획 수정 시 중복 생성 방지 |
| 6 | 작성 중 입력 복원과 저장 실패 안내 | 처음 열기, 새로고침, 불러오기 |
| 7 | 팀 소개와 글자 로고 적용 | 팀 이름·한 줄 소개 일치 |
| 8 | 반응형과 키보드 조작 검증 | 375px와 데스크톱 화면 |

## 5. 구현 기준

CSS 색은 변수로 관리합니다. 본문은 진한 색, 회색은 경계와 보조 그래픽에 사용합니다.
계획별 식별자를 부여하고 타깃 수와 시뮬레이션에 동일한 입력·계산 로직을 적용합니다.
미리보기는 텍스트로 구성하며 사용자 입력을 HTML로 실행하지 않습니다.
처음 여는 화면에 가상의 예시를 제공하고 데이터와 성과의 의미를 표시합니다.
예정 일시는 한국 시간 기준으로 저장·표시합니다.
저장 실패 시 현재 입력을 유지하며 안내를 보여줍니다.

## 6. 확인 방법

- 가상 고객의 연령·최근 접속·빈도·보유상품 필터를 각각 적용하고 조합합니다.
- 같은 상품을 여러 개 고른 경우에도 고객 수가 중복 집계되지 않는지 확인합니다.
- 1,000명, 클릭률 5%, 앱 방문율 80%에서 50명·40명인지 확인합니다.
- 비율 0·100%, 빈칸·음수·문자·범위 초과를 확인합니다.
- 저장한 캠페인을 다시 열고 수정할 때 동일 항목에 반영되는지 확인합니다.
- 새로고침과 저장이 제한된 상태를 확인합니다.
- 375px·768px·1440px에서 가로 스크롤과 메뉴·입력 접근성을 확인합니다.

## 7. 구현 전 확인

prd.md의 가정을 함께 검토하고 홈페이지 구현을 시작합니다.
로고는 초기 글자 표시로 진행하거나 사용자 제공 이미지를 적용할 수 있습니다.
