# 데이터마케팅팀 캠페인 업무 웹앱 PRD

| 항목 | 내용 |
|---|---|
| 문서 상태 | 초안 v0.1 |
| 작성일 | 2026-11-19 |
| 작성자 | EJ · 데이터마케팅팀 |
| 관련 문서 | logo-prompt.md, build-plan.md |

PRD는 누구를 위해 무엇을 만들고, 어떻게 완성 여부를 확인할지 정리한 기획서입니다.

## 1. 배경 · 문제

데이터마케팅팀은 고객 데이터를 분석해 마케팅 성과를 높이는 팀입니다. 디지털 마케팅 담당자는 앱 활성화 캠페인 기획, 타깃 설정, 푸시 메시지 작성, 발송 일정 관리와 예상 성과 확인을 한 화면의 흐름으로 처리하고자 합니다.

## 2. 목표와 성공 기준

| 목표 | 성공 기준 |
|---|---|
| 캠페인을 일관된 흐름으로 준비 | 캠페인명·목표 입력부터 타깃 설정, 메시지 작성, 일정 저장까지 완료 |
| 조건에 맞는 타깃 확인 | 조건을 바꾸면 예시 고객 기준 대상 수와 비율이 갱신 |
| 예상 성과 확인 | 예상 클릭 수와 앱 방문 수가 입력한 전환율에 맞게 계산 |
| 작성 내용 유지 | 새로고침 후 작성 중 입력과 저장된 캠페인이 복원 |

## 3. 대상 사용자

| 대상 | 필요한 정보 | 기대 행동 |
|---|---|---|
| 디지털 마케팅 담당자 | 타깃·메시지·일정·예상 성과 | 앱 이용 활성화 캠페인 기획 및 저장 |
| 경영진·리더 | 캠페인별 대상 규모와 예상 클릭·앱 방문 | 캠페인 계획과 기대 성과 검토 |
| 협업 부서 | 캠페인 목표·타깃·메시지·일정 | 캠페인 준비와 일정 조율 |

## 4. 기능 범위

- 캠페인명과 앱 활성화 목표를 작성합니다.
- 연령대, 최근 앱 접속일, 앱 이용 빈도, 보유 금융상품으로 예시 타깃을 필터링합니다.
- 푸시 제목·본문을 작성하고 모바일 알림 형태로 미리 봅니다.
- 예정 발송일·시각을 지정하고 캠페인 계획을 저장·수정합니다.
- 입력한 예상 클릭률과 클릭 후 앱 방문율로 클릭 수·앱 방문 수를 계산합니다.
- 저장한 캠페인과 작성 중 입력은 현재 브라우저에서 복원합니다.
- 팀 소개에는 “고객 데이터를 분석해 마케팅 성과를 높이는 팀”을 표시합니다.

## 5. 정보 구조

| 메뉴 | 화면 ID | 내용 |
|---|---|---|
| 캠페인 만들기 | campaign | 기획·타깃·메시지·일정 입력과 성과 요약 |
| 캠페인 일정 | schedule | 저장된 캠페인을 예정 시각순으로 조회·수정 |
| 팀 소개 | about | 팀의 역할과 주요 사용자 |

## 6. 화면 구성

데스크톱은 왼쪽 탐색 메뉴, 중앙 편집 영역, 오른쪽 예상 성과 요약으로 구성합니다.
중앙은 “기획·타깃”, “메시지·일정”을 순서대로 입력합니다.
휴대폰은 메뉴 버튼과 한 열 레이아웃으로 바꾸고, 성과 요약은 입력 영역 다음에 배치합니다.
일정 화면에서는 예정일, 캠페인명, 대상 수, 메시지, 예상 클릭·앱 방문을 확인합니다.

## 7. 콘텐츠와 동작 상세

### 7-1. 캠페인 기본 정보

- 팀 이름은 데이터마케팅팀입니다.
- 캠페인명, 목표를 입력합니다.
- 첫 실행은 가상 캠페인 “앱 다시 만나기”를 사용합니다 (가정).
- 처음 저장한 캠페인은 계획 목록에 추가하고, 불러온 캠페인은 같은 항목을 수정합니다.

### 7-2. 타깃 설정

| 조건 | 입력 방식과 의미 |
|---|---|
| 연령대 | 20대·30대·40대·50대·60대 이상 복수 선택, 선택 해제 시 전체 |
| 최근 앱 접속일 | 전체·최근 7일·8~30일 전·31~90일 전·91일 이상 전 중 선택 |
| 앱 이용 빈도 | 최근 30일 접속 횟수 기준 전체·0회·1~3회·4~9회·10회 이상 |
| 보유 금융상품 | 예금·적금·대출·펀드·카드 복수 선택 |
| 조건 결합 | 서로 다른 조건은 모두 충족, 같은 항목의 복수 선택은 하나 이상 충족 |

조건 선택지는 구현 초안의 가정입니다. 데이터는 재현 가능한 가상 고객 1,000건으로 구성합니다 (가정).
화면에는 “예시 고객 데이터”와 대상 수·전체 대비 비율을 표시합니다.
동일한 예시 고객이 여러 상품을 보유해도 대상 수는 한 명으로 계산합니다.

### 7-3. 푸시 메시지와 일정

- 제목과 본문을 직접 입력하고 실시간 미리보기를 제공합니다.
- 제목 30자, 본문 100자를 입력 안내 기준으로 사용합니다 (가정).
- 한글과 이모지는 Unicode 코드 포인트 기준으로 글자 수를 셉니다.
- 예정 발송일과 시각은 한국 시간으로 표시합니다.
- 일정 저장은 캠페인의 계획 상태를 관리합니다.
- 제목·본문·캠페인명·목표·유효한 미래 일정이 있어야 저장됩니다.
- 타깃이 0명일 때에는 조건 조정 안내를 보여주고 저장을 제한합니다.
- 과거에 저장한 계획은 예정 시각이 지났다는 상태와 함께 조회할 수 있습니다.

### 7-4. 예상 성과 시뮬레이션

| 항목 | 산식 |
|---|---|
| 예상 푸시 클릭 수 | 타깃 고객 수 × 예상 클릭률 ÷ 100 |
| 예상 앱 방문 수 | 예상 푸시 클릭 수의 반올림 전 값 × 클릭 후 앱 방문율 ÷ 100 |

표시되는 인원은 마지막 단계에서 각각 반올림합니다.
앱 방문 수는 푸시 클릭 후 앱에 도달하는 예상 인원으로 정의합니다 (가정).
입력률 범위는 0~100%이고, 빈칸·음수·문자·범위 초과에는 안내를 표시합니다.
처음 화면의 예상 클릭률 5%, 앱 방문율 80%는 편집 가능한 예시 값입니다 (가정).
예측 카드에는 “입력한 비율을 적용한 예상치”라는 안내를 둡니다.
타깃 수가 1,000명, 클릭률 5%, 앱 방문율 80%이면 클릭 50명·앱 방문 40명입니다.
0명이거나 비율이 0%이면 두 결과를 0명으로 처리합니다.

### 7-5. 저장 항목

작성 중 입력과 캠페인별 ID, 생성 시각, 수정 시각, 타깃 조건, 대상 수, 클릭률, 앱 방문율, 푸시 제목·본문, 예정 일시를 저장합니다.
가상 고객 자료는 초기 데이터로 유지하고, 화면에 표시할 대상 수를 같은 로직으로 계산합니다.
저장된 예측은 해당 계획의 입력값에 따라 복원합니다.
저장 실패 시 저장되지 않았음을 안내하고 현재 입력을 유지합니다.

## 9. 반응형 · 접근성

- 375px·768px·1440px 폭에서 입력과 결과를 사용할 수 있게 만듭니다.
- 작은 화면에서는 입력 항목과 요약을 한 열로 쌓습니다.
- 모든 입력에 연결된 라벨, 키보드 포커스, 선택 상태를 제공합니다.
- 색과 함께 숫자·문자로 상태를 전달합니다.
- 차트에는 같은 값을 확인할 수 있는 텍스트를 함께 표시합니다.

## 10. 기술 조건

index.html 한 파일에 CSS와 JavaScript를 포함해 로컬 브라우저에서 실행합니다.
localStorage의 전용 키로 작성 중 입력과 캠페인 목록을 저장하고 읽기·쓰기는 예외 처리합니다.
가상 데이터와 사용자 입력을 브라우저 내부에서 처리합니다.
메시지 미리보기와 일정 저장은 화면에서 확인할 수 있는 기능으로 구현합니다.

## 12. 완료 기준

- [ ] 요청한 네 가지 타깃 조건이 대상 수에 반영됩니다.
- [ ] 메시지 입력과 미리보기가 일치합니다.
- [ ] 캠페인 계획 저장·불러오기·수정이 동작합니다.
- [ ] 1,000명·5%·80%에서 클릭 50명·앱 방문 40명입니다.
- [ ] 잘못된 입력과 0명 대상에 안내가 표시됩니다.
- [ ] 새로고침 후 입력과 계획이 복원됩니다.
- [ ] 휴대폰 폭에서 가로 스크롤이 생기지 않습니다.
- [ ] 지정한 색 세 개와 한국어 화면을 사용합니다.
- [ ] 예시 데이터와 예상치의 의미를 화면에서 확인할 수 있습니다.

## 13. 확인할 가정

- 타깃 조건의 구간과 금융상품 선택지
- 첫 화면의 가상 고객 1,000건과 예시 캠페인
- 앱 방문 수를 “클릭 후 앱 도달”로 계산하는 정의
- 예시 클릭률 5%, 앱 방문율 80%
- 메시지 제목 30자·본문 100자
- 팀 로고 제공 전 글자 로고 사용
