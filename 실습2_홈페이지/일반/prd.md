# 운영팀 소개 페이지 기획서

| 항목 | 내용 |

## 1. 배경 · 문제

운영팀은 운영에 필요한 시스템을 관리한다. 현업 직원이 시스템을 사용하면서 도움이 필요할 때, 무엇부터 확인하고 언제 지원을 요청해야 하는지 한곳에서 찾을 수 있도록 한다.

## 2. 목표와 성공 기준

| 목표 | 확인 방법 |
|---|---|
| 현업 직원이 상황에 맞는 안내를 찾는다 | 예시 상황을 주고 첫 화면에서 해당 카드와 첫 조치를 찾을 수 있는지 확인한다. |
| 스스로 할 수 있는 범위와 지원이 필요한 시점을 이해한다 | 다섯 안내에 직접 확인할 일과 지원이 필요한 조건이 적혀 있는지 검토한다. |

## 3. 대상 사용자

업무 시스템을 쓰는 현업 직원. 지금 겪는 상황을 고르고, 안내를 따라 확인한 뒤 필요하면 정해진 지원 절차를 찾는다.

## 4. 범위

- 운영팀 한 줄 소개와 다섯 가지 상황별 안내를 한 페이지에 제공한다.
- 파일 업로드, 이미지 전달, 권한 신청 및 암호화 해제는 각 업무 시스템의 절차에 따라 진행하며, 이 페이지는 안내를 제공한다.

## 5. 정보 구조 (메뉴)

| 메뉴 | 섹션 ID | 담는 내용 |
|---|---|---|
| 상황별 해결 방법 | `#help` | 다섯 상황의 제목, 먼저 할 일, 지원이 필요한 경우 |

## 6. 화면 구성 (위에서 아래로)

헤더에 작은 로고 마크, 운영팀 이름과 메뉴를 둔다. 같은 마크를 브라우저 탭 아이콘으로 사용한다. 이어서 짧은 팀 소개와 “내 상황에 맞는 해결 방법을 골라 보세요”라는 문구를 보여 준다. 첫 화면에 운영 키워드 해시태그 20개를 보여 준다. 첫 화면에는 해결 방법 세 항목을 표시한다. 제목 오른쪽의 더보기는 등록된 안내를 모두 보여 주는 전체 목록으로 이동한다. 키워드를 선택하면 첫 화면에 표시되지 않은 안내도 바로 열 수 있다.

## 7. 콘텐츠 상세

### 7-1. 한 줄 소개

운영에 필요한 시스템을 관리하고, 현업에서 겪는 문제의 해결 방법을 안내합니다.

### 7-2. 상황별 해결 방법

아래는 공통 안내 초안이다. 시스템별 세부 절차는 공식 안내를 확인한 뒤 구체화한다.

| 상황 | 먼저 할 일 | 지원이 필요한 경우 |
|---|---|---|
| 화면이 안 열려요 | 공식 접속 경로를 다시 열고, 평소 사용하는 브라우저에서 새로고침한다. 오류가 계속되면 화면 이름과 오류 문구를 확인한다. | 다시 시도해도 화면이 열리지 않으면 시스템 지원 절차를 이용한다. |
| 권한이 필요해요 | 필요한 시스템과 메뉴, 사용 목적을 정리하고 공식 권한 신청 절차를 확인한다. | 필요한 권한이나 승인 담당자가 불명확하면 운영팀 안내를 확인한다. |
| 파일을 업로드하고 싶어요 | 허용 확장자와 용량을 확인하고, 업무 시스템에 지정된 업로드 화면을 이용한다. | 규격에 맞춰도 오류가 나면 오류 문구를 확인하고 지원을 요청한다. |
| 이미지를 전달하고 싶어요 | 받는 사람과 공유 범위를 확인하고, 업무에 승인된 전달 수단을 이용한다. | 외부 전달이나 추가 승인이 필요한 경우 공식 절차를 확인한다. |
| 암호화를 해제하고 싶어요 | 문서 열람에 필요한 권한과 공식 해제 절차를 확인한다. | 해제 권한이 필요하거나 절차가 불명확하면 담당자에게 요청한다. |

### 7-3. 푸터 연락처

실습용 대표 담당자는 임일반, 내선번호는 2345로 표시한다.

## 8. 디자인 가이드

첨부된 `trunk_style_design_guide.md`를 참고해 밝은 소개 영역에서 어두운 안내 영역으로 전환한다. 헤더는 알약형으로 배치하고, 오른쪽의 흑백 체크리스트 그림을 운영 안내에 맞게 그린다. 안내 목록에는 그림자 없이 가는 테두리를 쓰고 섹션 사이에 점선을 둔다.

| 색상 | 적용 |
|---|---|
| `#FFFFFF` · `#141416` | 밝은 소개 배경과 제목 |
| `#08090B` · `#232323` | 다크 본문과 펼친 안내 패널 |
| `#FFFFFF` · `#DDDDDD` · `#B3B3B5` | 다크 본문의 제목, 설명, 보조 문구 |
| `rgba(255,255,255,0.10)` | 어두운 영역의 패널 테두리와 구분선 |
| `#62C772` · `#EC592E` | 먼저 할 일과 지원이 필요한 경우의 상태 표시 |
| `#2F6EEB` · `#A5C2FF` | 키보드 초점과 다크 영역 링크 강조 |

고운돋움 보통 굵기를 사용한다. 해시태그는 알약 모양의 테두리를 두르고 글자 크기와 대비로 강조를 표현한다. 아코디언의 열림 상태는 오른쪽 꺾쇠와 펼쳐진 안내로 보여 준다.

## 9. 반응형 · 접근성

- 아코디언 항목은 모든 화면에서 세로 목록으로 배치한다. 펼친 안내의 두 설명은 넓은 화면에서 나란히, 좁은 화면에서 위아래로 배치한다.
- 키보드로 카드를 열고 닫을 수 있게 하고 초점 위치를 표시한다.
- 휴대폰 375px에서 글이 잘리거나 가로 스크롤이 생기는지 확인한다.

## 10. 기술 조건

`index.html`, `images/logo-icon.png`와 `fonts/`의 고운돋움 웹 글꼴로 구성한다. 카드 안내에는 HTML의 펼침 기능을 사용하고 브라우저에서 바로 연다.

## 11. 일정

기획 문서 확정 → 페이지 제작 → 데스크톱과 휴대폰에서 검토.

## 12. 완료 기준

- [ ] 헤더의 운영팀 이름 앞에 작은 로고가 표시되고, 브라우저 탭에서도 아이콘을 불러온다.
- [ ] 첫 화면에 키워드 20개가 표시되고, 각 키워드가 해당 안내 카드로 이동해 내용을 펼친다.
- [ ] 각 안내가 첫 조치와 지원이 필요한 경우를 설명한다.
- [ ] 모바일과 키보드에서 카드와 메뉴를 사용할 수 있다.

## 13. 열린 질문

실제 권한 신청 경로, 허용하는 파일 종류와 용량, 이미지 전달 수단, 암호화 해제와 문의 절차를 공개 가능한 범위에서 확인하면 안내를 구체화할 수 있다.
