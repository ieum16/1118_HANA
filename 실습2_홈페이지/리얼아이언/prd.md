## 1. 배경과 문제
협업 부서가 아키기획팀의 업무별 담당자와 요청 방법을 빠르게 확인할 수 있는 소개 페이지가 필요하다. 실제 업무 자료 대신 가상의 조직과 예시 연락 채널로 실습한다.

## 2. 목표와 성공 기준
- 방문자가 1분 안에 팀의 역할과 주요 업무 다섯 가지를 파악한다.
- 각 업무에서 해당 담당자를 찾아갈 수 있다.
- 협업 요청에 필요한 항목과 요청 순서를 확인하고 예시 요청 문구를 복사할 수 있다. 복사 기능은 가정이다.

## 3. 대상 사용자
주 방문자는 협업 부서 담당자다. 담당 업무, 연락 대상, 요청 준비 사항을 확인하려고 방문한다.

## 4. 범위
팀 소개, 주요 업무, 담당자, 협업 요청을 소개 페이지로 구현하고 프로젝트 인프라 예산 화면을 연결한다.
일반 협업은 요청문 복사로 준비한다. 프로젝트 예산은 공유 서버에 저장하고 접속자에게 실시간 갱신한다.

## 5. 정보 구조

## 6. 화면 구성
고정 헤더와 로고 → 팀 소개 → 주요 업무 다섯 가지 → 담당자 여덟 명 → 협업 요청 → 푸터.
상단에 담당자 확인과 협업 요청으로 이동하는 버튼을 제공한다.

## 7. 콘텐츠 상세
### 팀 소개
팀 이름은 아키기획팀이다.
한 줄 소개는 “본부 기획과 클라우드 운영 기획 업무를 조율하는 팀”이다.
대표 문구는 “사업의 구상을 구체화하고, 인프라 예산으로 잇습니다.”를 사용한다.
팀 규모는 팀장 1명과 팀원 7명, 총 8명이다.

### 주요 업무
- 본부 사업계획 수립 — 부서별 계획과 추진 과제를 정리한다.
- 월별 실적 보고 — 보고 항목과 제출 일정을 조율한다.
- 클라우드 운영계획 — 운영 과제와 실행 일정을 기획한다.
- 클라우드 비용 관리 — 예산과 사용 현황을 검토한다.
- 부서 간 일정 조율 — 회의와 협업 일정을 조정한다.
설명은 사용자에게서 받은 업무명을 바탕으로 작성한 가정이다.

### 담당자
실제 이름 대신 역할과 예시 닉네임으로 표시한다. 아래 배정은 가정이다.
- 팀장 — 아키리더, 총괄 조율
- 팀원 1 — 플랜, 본부 사업계획
- 팀원 2 — 리포트, 월별 실적
- 팀원 3 — 클라우드, 클라우드 운영계획
- 팀원 4 — 로드맵, 클라우드 운영 일정
- 팀원 5 — 버짓, 클라우드 비용
- 팀원 6 — 코디, 부서 간 일정
- 팀원 7 — 브릿지, 협업 접수와 진행 조율

### 협업 요청
예시 이메일은 team@example.com이다.
사업 목적·주사용자·서비스 대상 입력 → 환경 후보와 산정 기준 검토 → 기술팀별 규격·수량·단가 입력 → 가견적 취합 순서로 안내한다. 일반 협업 요청은 기존 요청문 복사 기능도 제공한다.
요청 양식은 업무 구분, 요청 내용, 희망 일정, 확인이 필요한 사항으로 구성한다. 이 절차와 양식은 가정이다.
가상의 팀을 소개하는 실습 페이지라는 문구를 푸터에 표시한다.

## 8. 디자인 가이드
- 메인 색 #008485. 하나은행을 연상시키는 청록 계열의 디자인 근사값으로 사용한다.
- 공식 CI 참고 https://www.hanafn.com/hfm/mnu/aboutus/hanaFnCi.do
- 공식 페이지에서 정확한 HEX 색상값을 확인하지 못했다.
- 기본 배경은 화이트 #FFFFFF, 섹션 배경은 밝은 쿨그레이 #F5F7FA로 구성한다.
- 제목은 딥 네이비 #172B3A, 본문은 차콜 #334155, 보조 설명은 슬레이트 #526174를 사용한다.
- 청록색 #008485는 로고, 주요 버튼, 선택 상태와 링크에 사용한다. 밝은 민트 #EAF5F2는 작은 강조 영역에 제한해 사용한다.
- 화면 면적은 흰색과 회색 약 80%, 남색과 차콜 약 15%, 초록 계열 약 5%를 출발점으로 균형을 맞춘다. 로고를 포함한 정확한 면적 비율은 레이아웃에 따라 조정한다.
- 헤더와 담당자 영역은 흰색, 주요 업무 영역은 밝은 회색으로 구분한다. 협업 요청 안내에는 작은 남색 영역을 사용해 전문적인 인상을 준다.
- 링크는 밑줄이나 명확한 버튼 형태로 구분하고 초록색만으로 상태를 표현하지 않는다. 흰 글씨 버튼은 더 진한 청록색 #006C6D를 사용해 가독성을 확보한다.
- 위 보조색과 배색 비율은 사용자가 요청한 깔끔하고 전문적인 분위기를 위한 디자인 제안이다.
- 분위기는 차분함, 믿음직함, 신뢰감이다.
- 로고는 images/logo.png이며 A 구조, 다리, 클라우드를 결합한 창작 로고다.
- 글꼴은 가독성 좋은 시스템 한글 글꼴을 사용한다.
- 넉넉한 여백과 얇은 구분선, 절제된 모서리를 사용한다.

## 9. 반응형과 접근성
375px와 1280px에서 가로 넘침 없이 표시한다.
업무와 담당자 정보는 데스크톱 다열에서 휴대폰 한 열로 바뀐다.
키보드로 메뉴와 버튼을 사용할 수 있고, 모바일 메뉴는 열림 상태를 알린다.
로고 대체 텍스트와 읽기 쉬운 색 대비를 적용한다.

## 10. 기술 조건
index.html에 소개 화면의 CSS와 JavaScript를 포함하고 images/logo.png를 참조한다.
budget.html, budget.js, budget-core.js, server.cjs를 추가해 공동 예산 기능을 구현한다.
Node.js 24에서 서버를 실행하고 같은 서버 주소로 접속한다. SQLite 데이터를 data/budgets.sqlite에 저장한다.
소개 페이지는 파일로 열 수 있고, 공동 예산 작업은 HTTP 서버를 통해 실행한다.

## 13. 검토할 가정

## 14. 프로젝트 예산과 환경 검토
사업별로 개요, 주사용자, 서비스 대상, 예상 이용 규모, 개발·검증·운영 환경, 가용성 요구, 자료 보관 및 자원 기준, 사용 일정과 과금 개월을 입력한다.

사업 설명은 담당 팀이 읽는 자료로 저장한다. 외부 클라우드 허용 여부, 전용 장비 필요성, 이용량 변동, 내부 클라우드 자원 유무, 빠른 개시 필요성의 답에 따라 환경 후보와 근거를 제시한다. 사업 설명의 자동 AI 해석은 구현 범위에 포함하지 않았다.
참고 자료 https://csrc.nist.gov/pubs/sp/800/145/final
우선순위 규칙은 이 도구에 정의한 참고 기준이며 환경의 최종 결정은 담당 팀 검토로 남긴다.

인프라팀, 네트워크팀, 클라우드플랫폼팀, DB팀은 품목명, 규격·산정 근거, 수량, 단위당 가격과 일회성·월 과금 방식을 입력한다.
수량과 단가는 직접 입력하거나 장비 종류를 선택해 기본 수량과 검토 규격을 채운다. 단가는 직접 입력한다. 초기 과금 기간 12개월, 예비비 0%, 부가세 10%는 변경 가능한 가정이다.
공급가액은 일회성 비용과 월 비용에 과금 개월을 곱한 금액의 합계다. 예비비를 더한 뒤 부가세를 적용하며 각 단계는 원 단위 반올림한다.
날짜로 기간 채우기는 시작 월과 종료 월을 모두 포함하고 일할 계산을 하지 않는다.
가격은 시장 가격 조회 없이 입력값으로 계산하며 실제 비용은 회사 기준으로 확정한다.

## 15. 공동 편집과 데이터
사업과 품목별 필드를 비교해 서로 다른 항목의 동시 변경은 합친다. 같은 필드의 상충하는 수정은 409 충돌로 알려 최신 내용과 비교하도록 한다.
저장되지 않은 입력은 다른 접속자의 갱신으로 덮어쓰지 않는다. 사업 삭제는 최신 버전 일치 여부를 확인한다.
작성자 닉네임과 최근 저장 시각을 표시한다. 접속자는 모든 팀 자료를 공동 편집할 수 있다. 팀 탭은 담당 구분용이다.
CSV는 현재 입력 내역과 가견적을 내려받고, JSON은 현재 사업 데이터의 사본을 내려받는다.
서버 PC의 data 폴더에 데이터가 유지되며 서버를 재시작해도 불러온다. 서로 다른 서버를 실행하면 서로 다른 데이터 저장소가 된다.

## 16. 3티어·이중화와 장비 카탈로그
모든 사업의 기본 아키텍처는 WEB·WAS·DB 계층 분리와 전 장비 이중화다.
장비별 기본 수량 2개, 최소 수량 2개를 적용한다. N+1 등 확장 구성을 위해 3개 이상도 입력할 수 있다.
기본 구성은 물리서버 기준으로 WEB·WAS·DB 서버, SAN 스토리지, L3·L4 스위치, 방화벽, VPN 각각 2개다. 이는 가견적 입력을 위한 구성 가정이다.
카탈로그에는 기본 서버, NAS, 백업, WAF, IPS, 프라이빗·퍼블릭 VM, 프라이빗 호스트, DB 전용 장비도 포함한다.
장비 선택 시 용도 중심의 검토 규격과 계층을 채운다. 성능 규격과 가격은 담당 팀이 산정한다.
기존 데이터의 수량·가격을 유지하며 새 메타데이터만 공통 계층·직접 입력으로 해석한다.
미완성 계층은 작성 중으로 저장할 수 있고 견적에 구성 검토 중 표시를 한다. 수량 1개는 서버에서도 저장을 거절한다.
수량·계층 충족과 실제 고가용성 검증을 구분해 안내한다. 독립 장애영역, 전원·경로, 복제·절체는 기술팀 검토 대상이다.

## 17. 통합 디자인 적용
소개 화면은 흰색·쿨그레이를 기본으로 넉넉한 여백과 큰 제목, 기존 로고를 사용한다. 인프라 예산 소개에 남색 배경을 적용하고 초록색은 주요 행동과 제목 강조에 사용한다.
예산 작업 화면은 사업 설명부터 작성하고 기본 아키텍처, 환경 검토, 장비 입력, 계산 기준으로 이어진다.
PC에서 견적 요약을 고정하고 총액을 우선 표시한다. 기간·예비비·부가세 내역과 팀별 비용은 펼쳐서 확인한다.
모바일에서는 고정 하단 총액·저장 버튼을 제공하며 문서 하단 여백을 확보한다.
기존 공동 저장·검증·계산·환경 규칙을 유지하며 저장된 사업 데이터에 대한 디자인 변경 작업은 읽기 전용으로 수행했다.
